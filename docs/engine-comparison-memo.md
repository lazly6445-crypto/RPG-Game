# 엔진 비교 메모 (P0 1주차)

> 목적: P0 엔진 게이트(`dev-roadmap.md` §2, `gdd-1.0.md` §12) 전에 Unity · Godot · Unreal의 **확인된 사실**과 **미확인 사항**을 구분해 정리하고, 게이트 순서를 정한다.
> 작성 근거: 2026-11-01 웹 검색 결과(대부분 2차 자료). 공식 문서 직접 열람은 일부만 가능했고, 각 항목에 **확인 수준**을 적었다.
> 확인 수준: **A** 공식 문서/약관 원문 확인(요약 포함) · **B** 신뢰할 만한 2차 자료 · **C** 포럼·마켓 페이지·벤더 홍보 · **미확인** 검색으로 확인하지 못함.
> 이 메모의 순위와 의견은 **제안**이며 최종 엔진은 P0 4주차 게이트에서 실측으로 확정한다.

## 1. 요약

| | 결론 |
|---|---|
| 순위 의견(갱신) | **1순위 Godot(조건부) → 2순위 Unity → 3순위 Unreal.** 이전 문서(`dev-roadmap.md` §2 초안)의 Unity 1순위를 이번 조사로 바꿨다 |
| 바꾼 이유 | 이 게임의 독자 요소는 **런타임 지형 변형**(결정 1)이다. Godot에는 이를 직접 지원하는 **무료 오픈소스** 확장(Voxel Tools)이 있고, Unity·Unreal에서는 같은 기능을 **유료 에셋/플러그인** 또는 **직접 구현**으로 얻어야 한다(검색 확인). 결정 11(외주·에셋 구매 없음)·결정 93(도구 월 5만 원 이하)과 충돌하는 쪽은 Unity·Unreal이다 |
| 조건 | Voxel Tools가 **최저 사양(통합 그래픽/엔트리 GPU, RAM 8GB, 30fps)** 에서 변형·스트리밍을 감당하는지는 **검증 전**이다. 이 게이트를 통과하지 못하면 Unity로 간다 |
| 불확실성 | 숙련 엔진이 없으므로 학습 비용은 세 엔진 모두 같다고 가정했다. Godot의 대형 월드 스트리밍은 조사에서 확인하지 못했다 |

### 3.2 런타임 지형 변형 (R1) — 이 게임의 핵심
| | Unity | Godot | Unreal |
|---|---|---|---|
| 기본 지형 | Terrain은 **높이맵 기반**(동굴·오버행 불가, B). `SetHeights`로 런타임 수정 가능하나 포럼 보고는 오래된 자료이며 동기식 부담이 있다고 한다(C) | 지형 확장 Terrain3D 등(요약에 변형 지원 상세 없음, **미확인**) | Landscape는 런타임 변형이 기본 지원되지 않는다는 취지의 정보를 **공식 문서로 확인하지 못함**(**미확인**) |
| 런타임 변형 솔루션 | **유료 에셋**: Digger PRO(높이맵+복셀 메시, 실시간 편집은 PRO 등급, Unity 2022.3 이상, C), Ultimate Terrains, Voxelform 등 오래된 자료(C) | **Voxel Tools for Godot**(C++ 확장, 오버행·터널·**게임 내 실시간 편집**, 청크를 페이징해 무한 지형, 비파괴 모디파이어, 변경 로그에 청크 경계 메시 구멍 버그 수정 이력, **오픈소스**) (B) | **유료 플러그인**: TerraDyne(Landscape→런타임 편집 가능 다이내믹 메시, 청크 스트리밍·LOD, 벤더 페이지 v0.4.5), ButterNet Multiplayer Voxel(복셀, 저장·로드) (C, 벤더 홍보) |
| 비용·R5 충돌 | 유료 에셋 구매 → **결정 11과 충돌 소지**, 직접 구현은 큰 작업 | **무료**, R5 충족 | 유료 플러그인 → R5 충돌 소지, 직접 구현 필요 |
| 성능 근거 | 높이맵 갱신 비용 일부 보고(0.1~0.2ms/33×33, 오래된 포럼, C). 최신 공식 벤치마크 **미확인** | 대규모 변형 벤치마크 **미확인** | **미확인** |

> 결정 11 해석 주의: "외주·에셋 구매 없음"에 **유료 플러그인 구매가 포함되는지** 사용자 확인이 필요하다. 오픈소스·무료 확장(예: Voxel Tools)은 구매가 아니므로 충돌하지 않는다고 본다. **[제안, 사용자 확인 필요]**

## 5. 지형 변형 방식 후보와 엔진 매핑 (프로토타입 D)

GDD §7.2의 구현 후보 3가지(높이맵 / 복셀·청크 / 격자 블록)와 엔진별 현실성.

| 방식 | 장점 | 단점 | Unity | Godot | Unreal |
|---|---|---|---|---|---|
| 높이맵 편집 | 단순, 저비용 | 동굴·오버행 불가 → 던전 입구·터널 표현에 제약 | 기본 Terrain | Terrain3D(변형 지원 **미확인**) | Landscape(런타임 변형 **미확인**) |
| 복셀/청크 | 자유도 높음, 오버행·터널 | 메모리·메시 생성 비용, 델타 저장 설계 필요 | 유료 에셋 | **Voxel Tools(무료)** | 유료 플러그인 |
| 격자 블록 | 저폴리 화풍과 궁합, 구현 쉬움, 델타 저장 단순 | 부드러운 지형이 아님(화풍에 따라 장점) | 직접 구현 | 직접 구현 | 직접 구현 |

- 던전은 지하 공간이다(GDD §6.1). 높이맵만으로는 던전 내부의 변형(대형 전투방 함정·함몰)이 표현하기 어려울 수 있다. 복셀 또는 격자 블록이 던전과 필드를 같은 방식으로 다룰 수 있는 장점이 있다. **[제안]**
- "격자 블록" 방식은 어떤 엔진에서도 직접 구현 가능하므로 **복셀 확장 검증이 실패하는 경우의 엔진 독립 퇴로**다. 퇴로로 삼으면 엔진 선택이 지형 변형에 덜 묶인다.

## 6. 게이트 계획 제안 (P0 1~4주차) **[제안]** — 상세 측정 계획: `engine-gate-plan.md`

| 주 | 작업 | 산출물 |
|---|---|---|
| 1 | 아래 §7의 확인 항목을 공식 문서로 확인. 세 엔진의 현재 버전·약관·최소 요구 사양을 메모 | 이 메모의 미확인 항목 채움 |
| 1~2 | **Godot + Voxel Tools**로 최소 테스트: 3인칭 이동 + 땅 쌓기·깎기 + 최저 사양 기기(또는 동등 제한) 실행 | 프레임타임, 편집 지연 |
| 2~3 | 같은 최소 테스트를 **Unity**(높이맵 `SetHeights` 또는 직접 격자 블록)로 반복 | 비교 수치 |
| 3~4 | 더 나은 쪽으로 스트리밍 테스트 월드, 변형 100곳 저장·불러오기, 건축물 아래 변형 규칙 | 게이트 판정 |

- 1인 파트타임이므로 두 엔진 모두 완성도 있게 만들지 않는다. **같은 최소 시나리오 1개**만 만든다.
- 합격선은 로드맵 §2의 게이트 기준을 따른다: 최저 사양에서 이동·변형 중 히치 없음 / 하루 내 수정·재실행 / 편집→배치→플레이 왕복 10분 이내 **[가정]**.
- Godot가 합격하면 Godot, 불합격이면 Unity로 간다. Unreal은 위 둘이 모두 불합격일 때의 3순위로만 둔다(지형 변형은 유료 플러그인 필요).
