# 프로토타입 A — 2D 전투 감 사양 (P0)

> 근거: `dev-spec-phases.md` P0-3 A, `gdd-1.0.md` §7.5, `2d-transition-impact.md`(3D 요소 개정 필요). 엔진: Godot 4.7.2(결정 127). 코드는 게임 PC `D:\gate-godot`에 추가한다(프로토타입 단계라 같은 저장소 사용).
> 표기: **[제안]** 제안 · **[가정]** 임시값 · **[측정]** 플레이테스트로 조정. 아래 모든 수치는 **데이터 파일**에 두며 코드에 박지 않는다.

## 1. 질문과 성공 기준
- 질문: 2D 탑다운에서 이동·회피·공격이 "한 번의 조작이 즐거운가"(GDD §6의 몇 초 단위 재미)를 만족하는가?
- 성공 기준 **[가정]**: 처음 해보는 테스터 5명 중 4명이 설명 없이 회피와 공격을 사용하고, 같은 적과 3번 반복해도 지루하다고 하지 않는다. 숙달 없이도 이긴다(GDD §7.5).
- 범위 밖: 자세 게이지·스태미나 전투(GDD §7.5에서 도입하지 않음 **[제안]**; 이 프로토타입에서 필요하다고 느껴지면 기록만), 주목(락온, 3D 잔재 — 2D에서는 불필요), 무기 내구도(없음, 결정 9번).

## 2. 플레이어 동작 **[제안]**
| 동작 | 입력(키보드) | 규칙 |
|---|---|---|
| 이동 | WASD/방향키 | 8방향. 기존 `GridMover` 높이 규칙(오르기 1단, 2단 벽 막힘, 낙하) 그대로 사용 |
| 공격 | J | 바라보는 방향 근접 1타. 선딜(windup)→판정(active)→후딜(recovery) 3구간. 판정 모양은 부채꼴 또는 전방 사각형(데이터로 선택) |
| 회피 | Space | 짧은 구르기. 이동 방향(없으면 바라보는 반대 방향). 무적 구간(i-frame)과 후딜, 재사용 대기 |
| 입력 버퍼 | — | 후딜 마지막 N프레임 안의 입력은 저장했다가 가능해지는 즉시 실행(공격↔회피) |
| 취소 | — | 공격 후딜은 회피로 취소 가능, 회피 후딜은 취소 불가 |

초기 수치 **[가정, 측정]**(데이터 파일): 이동 96px/s(기존), 공격 선딜 80ms·판정 100ms·후딜 180ms, 히트스톱 60ms, 회피 거리 96px(3타일), 회피 시간 220ms, 무적 0.12~0.18초 구간, 재사용 대기 400ms, 입력 버퍼 120ms.

## 3. 적 1종 **[제안]**
- 근접 추격형 소형 적 1종(탑다운에서 읽기 쉬운 단색 사각형 + 방향 표시). 플레이어와 같은 높이 규칙으로 이동(`GridMover` 재사용 가능 여부는 구현 시 판단, 안 되면 직선 추격 + 높이 차 2 이상 막힘).
- 행동: 추격 → 사거리 진입 시 **예비동작(telegraph)** 0.4초(색 점멸 + 약간 뒤로 물러남) → 공격 판정 → 후딜(반격 기회) → 재추격. 예비동작이 읽히지 않으면 실패.
- HP/피해: 플레이어 HP 5 칸, 적 HP 3 **[가정]**. 피격 시 넉백(타일 단위 짧게)과 히트스톱, 화면 흔들림(작게, 옵션으로 끔).
- 난이도 옵션(GDD 절대수칙 1): 받는 피해 배율 `0.5 / 1.0 / 1.5`를 데이터로.

## 4. 피드백(게임 감)
히트스톱(양쪽 모두 정지), 카메라 흔들림(약), 피격 플래시, 적 피격 반응(넉백·점멸), 공격 판정 시각화(디버그 키로 히트박스 표시), 간단한 효과음 자리(오디오는 이번 범위 밖, 호출 지점만 남김).

## 5. 구현 구조 **[제안]**
- 전투 로직은 **노드 없이 테스트 가능한 순수 로직**으로 분리(상태기계: Idle/Move/Windup/Active/Recovery/Dodge/Hitstun/Hitstop), 렌더·입력은 얇은 씬이 맡는다. 기존 `Terrain`/`GridMover` 패턴과 같다.
- 수치는 `data/combat.json`(또는 Godot Resource) 한 곳. 잘못된 값 검증 포함.
- 헤드리스 테스트: 프레임 데이터가 설계대로 진행되는지, 무적 구간 안 피격 무시, 입력 버퍼 동작, 후딜 취소 규칙, 히트스톱 동안 시간 정지, 적 예비동작 타이밍, 높이 규칙과의 상호작용(2단 벽 앞에서 추격 막힘).
- 확인 씬: 지형 위에 플레이어 + 적 1~3 마리 소환(키), 수치 라이브 조정은 하지 않고 데이터 파일 수정 후 재실행.
- 플레이테스트 계측: 이벤트 로그(CSV) — 공격 시도·명중, 회피 시도·성공(무적 중 피격 회피), 피해, 사망, 전투 시간. 테스터 세션별 파일.

3. 부채꼴 vs 전방 사각형 판정 [제안: 사각형으로 시작, 데이터로 전환].
4. 플레이어 HP 표시 방식(칸/숫자) [미결정, 임시: 화면 좌상단 칸].
5. 프로토타입 B(규칙)·C(이동)와 합칠 시점: A의 성공 기준 판정 후.
