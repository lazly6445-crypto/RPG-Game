## P0. 프리프로덕션 (3개월)

### P0-1. 목표
기둥(로드맵 1장)을 실제 조작으로 검증하고, 엔진과 스코프의 큰 방향을 정한다. 아트·콘텐츠 제작은 하지 않는다.

### P0-2. 작업 목록

| 주차 | 작업 | 산출물 |
|---|---|---|
| 1 | 엔진 라이선스·지형·스트리밍 사례를 공식 문서로 확인, 개발 환경·버전관리(대용량 에셋 지원)·빌드 자동화 구성 | 엔진 비교 메모, 레포 구조 |
| 1~4 | **엔진 게이트**: 스트리밍 테스트 월드(저폴리곤 지형+식생 인스턴싱), 최저사양 기기 측정 | 프레임타임 그래프, 판정 |
| 2~6 | 프로토타입 A **전투 감**: 이동, 회피, 주목 카메라, 공격 1종, 적 1종 | 플레이 가능 빌드 |
| 3~8 | 프로토타입 B **규칙 상호작용**: 원소/물리 규칙 2~3개의 조합 | 조합 매트릭스 표, 데모 룸 |
| 4~8 | 프로토타입 C **이동**: 달리기, 점프, 오르기, 활공 중 최소 2개 | 지형 테스트 맵 |
| 6~10 | 화풍 실험: 저폴리곤 팔레트·조명·포스트프로세싱·VFX 스타일 3안 | 화풍 가이드 초안 |
| 8~12 | 설계 문서 확정: 세계관 1쪽, 주인공, 메인 구조, 월드 구성 개요 | GDD 1.0 |
| 12 | 스코프 가안, 컷 회의 | 콘텐츠 목표 가안 |

### P0-3. 프로토타입 상세

**A. 전투 감 (R 8.1~8.3, Z 5장 "적 표현 과장")**
- 필수: 입력 버퍼, 선행 입력 취소 창 규칙, 히트스톱, 카메라 흔들림, 피격 반응, 적 예비동작 가독성.
- 선택 검토: 자세(posture) 게이지(세키로, R 8.3)와 스태미나 중 하나만 선택. 둘 다 넣지 않는다. **[제안]**
- 무기 내구도: **없음(확정, 부록 B 9번)**. 근거: Z 7장에서 BotW 내구도가 전투 흐름을 끊는다는 비판.
- 수치: 이동속도, 회피 무적 프레임, 공격 선딜/후딜은 **[측정]**(플레이테스트로 조정). 임의 초기값은 코드가 아니라 데이터 테이블에 둔다.
- 성공 기준: 처음 해보는 테스터 5명 중 4명이 설명 없이 회피·공격·주목을 사용하고, 같은 적과 3번 반복해도 지루하다고 하지 않는다. **[가정]**

**B. 규칙 상호작용 (곱셈형 설계, Z 3.11, 5장)**
- 규칙 후보(4개 이내 **[가정]**): 불(점화·연소), 물(젖음·전도·부력), 바람(운반·확산), 무게(누름·부력).
- 구현 방식 **[제안]**: 오브젝트가 **속성 태그**와 **상태**를 갖고, 규칙은 "태그+상태+자극 → 결과" 표(데이터)로 정의한다. 규칙 추가가 코드 수정 없이 표 수정이 되게 한다.
- 조합 매트릭스: 규칙×오브젝트 종류 표를 문서로 관리하고, 각 칸에 의도한 결과 또는 "정의 안 함"을 적는다(TotK는 조합을 하나하나 손으로 조정, Z 3.12).
- 제어 가능성: 창발은 통제 가능한 범위에서 시작한다(R 7.4). 규칙 수가 늘면 자동 시뮬레이션 테스트로 결함을 잡는다.
- 성공 기준: 퍼즐용 전용 오브젝트 없이 규칙만으로 서로 다른 해법이 2개 이상인 데모 상황 3개를 만들 수 있다. **[가정]**

**C. 이동 (R 4.1, Z 7장)**
- 이동기가 월드 체감 크기와 탐험 동기를 만든다(R 4.1). 반대로 강한 이동 도구는 탐험을 잠식한다(Z 7장 TotK 탈것).
- P0에서는 달리기+점프+오르기(스태미나 소모)부터. 활공·탈것은 슬라이스에서 판단.
- 성공 기준: 지형만 보고 "저 봉우리까지 오르고 싶다"가 테스터 발언으로 나온다.

**D. 지형 변형 (결정 1, 독자 핵심 요소)**
- 질문: 플레이어가 땅을 쌓고 깎을 때 (1) 입력 지연, (2) 변형 결과의 저장 크기, (3) 스트리밍 경계에서의 일관성, (4) 충돌·내비게이션 갱신 비용이 어느 정도인가.
- 구현 후보 **[제안, 미검증]**: 높이맵 편집(단순, 동굴·오버행 불가), 복셀/청크 지형(자유도 높음, 메모리·메시 생성 비용 큼), 격자 블록(저폴리곤 화풍과 잘 맞고 구현 쉬움). 후보별 비용은 조사에 없으므로 실측한다.
- 저장: 원본 지형은 읽기 전용, 변형은 **차이(델타)만 세이브에 저장**하는 구조를 기본안으로 시험한다. **[제안]**
- 젤다식 퍼즐과 연결: 지형 변형이 해법이 되는 퍼즐 데모 3개(다리 만들기, 물길 돌리기, 벽 쌓아 오르기).
- 성공 기준: 최저사양에서 변형 중 30fps 유지, 변형 100곳 저장·불러오기 후 세이브 용량 증가량이 목표(**[측정]**) 이내, 스트리밍 경계에서 틈·튕김 없음. **[가정]**
- 실패 시 변형 범위를 축소(부록 B의 1인 개발 영향).

### P0-4. 엔진 게이트 상세
- 테스트 월드: 8~16km² **[가정]** 지형, 식생 인스턴싱, 저폴리곤 건물 더미. 구체 면적은 목표 월드 크기 가안(P0 종료)보다 크게 잡아 여유를 확인한다.
- 측정 항목: 평균/99퍼센타일 프레임타임, 이동 중 히치 횟수, 메모리, 디스크 용량, 스트리밍 반경과 로딩 지연, 빌드 시간.
- 판정은 로드맵 2장 기준. 못 통과 시 대안 순서는 로드맵 2장.
- 참고: Unreal의 월드 파티션은 셀 단위 스트리밍(예시 셀 256m, 로딩 범위 768m는 **문서의 예시값**)을 공식 제공한다(R 18.4). Unity/Godot를 쓰면 이에 해당하는 시스템을 직접 만든다고 가정하고 일정에 반영한다. **[가정]**

## P1. 수직 슬라이스 (6개월)

### P1-1. 목표
한 지역을 **출시 품질**로 완성해 (1) 재미를 재확인하고 (2) 콘텐츠 1단위당 제작 시간을 실측한다(R 14.3: 슬라이스는 데모가 아니라 파이프라인 측정 도구). 폴리싱된 슬라이스가 미해결 문제를 가릴 수 있다는 경고(R 14.3, C)가 있으므로 **최저사양 기기에서 항상 돌려 본다**(R 14.4).

### P1-2. 슬라이스 범위 **[가정]**
- 지역 1개(예: 1~2km²), 거점(마을) 1개, 필드 POI 15~25개, 소형 던전 1개, 보스 1개, 주요 퀘스트 1줄 + 사이드 퀘스트 3개, 이동기 2~3개 해금.
- 플레이 시간 목표 30~60분.
- 슬라이스에 넣는 이유: 스카이림식 이동(산이 직선 이동을 막음, R 4.1), BotW식 삼각형 규칙(Z 3.11), 엘든 링식 "보스 먼저 놓고 지형을 맞춤"(R 4.5)을 한 지역에서 모두 시험한다.

### P1-3. 월드 사양

**지형 제작 방식 [제안]**: 완전 절차 생성이 아닌 **수작업 큰 틀 + 도구 보조 산포**. 근거: 젤다류는 랜드마크 배치가 핵심이고(Z 3.11), 규칙 기반 산포는 편집 가능해야 한다(R 4.6 호라이즌 사례: 아티스트가 규칙을 수정 가능).
1. 큰 틀: 핵심 지점(보스, 마을, 던전 입구, 대형 랜드마크)을 먼저 배치(R 4.5).
2. 지형 조형: 삼각형 규칙(큰 삼각형=랜드마크, 중간=경로 차폐, 작은 것=속도 조절, Z 3.11)에 맞춰 산·능선·계곡 구성.
3. 산포: 식생·바위·소품은 규칙 기반 도구로 배치 후 수작업 보정.
4. POI: 자원·적·보상을 미니 클러스터로 묶는다(R 4.2, 18.3 Luban 2부: 자원은 흩뿌리지 말고 POI에 묶는다).

**POI 규칙 [제안]**
- 어디서나 지평선에 성격이 다른 POI가 최소 3개 보이게(R 4.2 "다양성 규칙", C라 검증 필요).
- 각 POI는 명확한 보상 1개(BotW 사례: 사당→체력/스태미나, 적 진지→무기, 마구간→회복·상점, 18.3 GMTK 요약).
- 이동 간격: 60~120초(R 4.2, 단일 블로그 경험칙, **[측정]** 필수). 슬라이스에서 실제 이동 속도로 간격을 재서 확정한다.
- 소형 랜드마크도 멀리서 읽혀야 한다(사당 발광, 연기, 특징적 바위, 18.3 GMTK 요약). 저폴리곤이라 **실루엣과 색**으로 구분한다. **[제안]**
- 건너뛰는 구역은 플레이테스트로 찾아 은은한 표지를 추가(Z 3.11).

**레벨 디자인 문법 [제안]** (R 18.3 Luban 3부): 자원 배치 규칙(예: 특정 식물은 특정 환경에만), 등반·통과 가능한 면의 시각 단서, 문 폭·점프 높이 등 크기 표준 템플릿을 문서로 고정한다.

### P1-4. 전투·성장 사양
- 적 3~5종 + 보스 1. 적마다 서로 다른 규칙 반응(불에 약함 등)을 부여해 곱셈형 규칙과 연결.
- 보스: 월드에 먼저 배치하고 지형을 맞춤(R 4.5). 보스가 이동기/도구를 준다(발헤임·젤다의 보스 보상, R B.6).
- 성장: 슬라이스에서는 **능력 해금 중심**(이동기, 도구), 수치 성장은 최소(R 9.4, Z 아이템 게이팅). 레벨 스케일링은 **쓰지 않는다**(지역 고정 위험도, R 9.1 [제안]).
- 장비 요구 조건을 사후에 올리지 않는다(R 9.1 위쳐 3 패치 사례의 교훈).

### P1-5. 퀘스트·서사 사양
- 메인 1줄 + 사이드 3개. 사이드마다 감정·장소·메카닉이 달라야 한다(R 5.3). 수집·배달 최소화.
- 퀘스트 제작 파이프라인: 피치→폐기→초안→임시 에셋 구현(R 5.3). **슬라이스에서 한 퀘스트를 만드는 데 걸린 시간·인원·폐기율을 기록**한다. 이 값이 P2 스코프 계산 입력이다.
- 서사 원칙 후보(R 18.3 Sasko, 기사 요약): 불필요한 반복 설명 제거, 정보는 집중된 순간에, 설명은 환경으로, 선택의 결과는 플레이어에게 보이게. 사이드는 필러가 아니라 세계/인물을 드러내야 함.
- 대사량·현지화는 R B.3 참고(비용 수치는 미확인). 한국어 우선, 외 언어는 P3 이전에 결정.

### P1-6. UI·내비게이션·온보딩
- 지도: 기본은 **마커 최소**(환경이 안내). 가이드 모드 옵션으로 마커 밀도를 올릴 수 있게(R 11.1 [제안], Z 수칙 1).
- 나침반: 추적 퀘스트와 플레이어 웨이포인트는 항상, 그 외는 반경 내에서만(R 11.1, C).
- 온보딩: 첫 10분 안에 이동·전투·규칙 상호작용 1개를 체험시키되 튜토리얼은 스킵 가능(Z 7장 피 튜토리얼 비판). 숙달감·목적감·몰입감(R 11.2).
- 접근성: 키 리매핑, 자막 크기, 색약 대응, 난이도 옵션 초안을 슬라이스에서 구현(처음부터 계획해야 가능, R 11.3).

### P1-7. 사운드
- 환경음 중심, BGM 절제(Z 3.11, R 12). 전투/탐험/마을 3종 음악 레이어를 먼저 만들고 스템 전환 구조를 적용(R 12 RDR2 사례 방식은 규모가 달라 축소 적용). **[제안]**

### P1-8. 기술 사양
- 스트리밍: P0에서 검증한 방식을 슬라이스에서 실콘텐츠로 재측정.
- 데이터 중심: 아이템·적·퀘스트·규칙표를 데이터 파일로 분리, 이후 모드/에디터 공개 가능성을 열어 둔다(R 17.6).
- 세이브: 버전 필드와 마이그레이션 훅을 처음부터 둔다. **[제안]**
- 자동화: 빌드 서버, 스모크 테스트(맵 순회 봇), 규칙 조합 자동 테스트.
- 계측: 플레이 위치 히트맵, 이탈 지점, 사망 지점 로그(플레이테스트용).

### P1-9. 슬라이스 측정 항목 (가장 중요)
| 측정 | 용도 |
|---|---|
| 1km² 지형 제작 인일 | P2 월드 제작 기간 |

## P2. 콘텐츠 제작 / 알파 (10개월)

### P2-1. 목표
확정된 스코프만큼 월드·던전·퀘스트·적·시스템을 만든다. 마지막에 **엔딩까지 거친 상태로 플레이 가능**해야 한다.

### P2-2. 제작 순서 **[제안]**
1. 월드 골격: 전체 지형, 거점, 핵심 지점(보스·던전 입구) 배치(R 4.5).
2. 메인 퀘스트 한 줄 관통(순서 고정 구간은 첫 구간만, R 18.3 Luban 2부 "첫 클러스터는 온보딩").
3. 던전·보스를 진행 순서대로(이동기/도구 해금 흐름과 동기화).
4. 필드 POI 채움: 지역별로 변주 확보(Z 수칙 9: 새 지역마다 다른 규칙·위협·보상).
5. 사이드 퀘스트: 폐기율을 감안해 확정 수의 1.3~1.5배 피치 **[가정]**(R 14.5-2 "폐기 비율을 제작비에 반영").
6. 경제·상점·루팅.
7. 사운드·음악 본제작.

### P2-3. 월드 구성 규칙 **[제안]**
- 지역 수 3~5개 **[가정]**, 지역마다 고유한 (1) 위협 (2) 자원 (3) 환경 규칙(예: 추위, 독, 습도)을 둔다. 새 지역이 시각만 다르면 실패(R 18.3 Luban 2부, Z 7장 "지역 단조로움").
- 지형 규칙: 이동 차단은 임의 장벽이 아닌 게임플레이 조건(도구·환경 조건)으로(Luban 2부, 파크라이 프라이멀의 추위 사례).
- 손으로 만든 "정수" 구역(레거시 던전급, R 17.2)을 정하고 예산을 집중한다. 나머지는 도구 보조.
- 빠른 이동: 도입 시 비용·제한을 둔다(발헤임 포털의 "광석 불가" 사례, R B.6 [근거, 해석은 C]).
- 하늘/지하 같은 수직 확장은 슬라이스에서 효과가 입증될 때만. 입증 전에는 후보에서 제외. **[제안]**

### P2-4. 전투·성장·경제
- 성장 축 2개(능력 해금 + 소량 수치/빌드). 스킬 트리를 쓰면 노드는 새 선택지를 열어야 하고 +%만 쌓는 필러를 피한다(R 17.4, 18.5 스카이림 퍽 비판).
- 스탯 스케일링을 쓴다면 체감 곡선을 표로 설계하고 체감 구간(초반 급상승→완만)을 목표 곡선으로 먼저 그린다(엘든 링 스케일링 곡선 사례, R 18.4 [근거 C]).
- 경제: 시작 전에 수입 총량 대비 예상 지출을 계산하고 실제 플레이로 비교(R 18.5 슈워츠 요약), 영구 업그레이드 대신 일시 소모품 활용, 화폐 종류를 옆으로 확장(요약 내용, 원문 미확인). **[제안]**
- 유료 랜덤 요소(확률형)는 두지 않는다(로드맵 6장).

### P2-5. 퀘스트·서사
- 목표 수치 **[가정]**: 메인 1줄(8~12 구간), 사이드 20~30개(폐기 전 30~45개 피치), 거점 NPC 15~25명. 이 숫자는 P1 측정값이 나오면 교체한다.
- 제작 규칙: 퀘스트 설계서 1쪽(감정/장소/메카닉/보상/실패 조건), 퀘스트마다 서로 다른 점을 한 줄로 쓴다(R 5.3).
- 선택·결과: 결과는 지연돼도 플레이어에게 보이게(Sasko 10가지 교훈 기사 요약, R 18.3). 분기는 최소로, 변수로 흔적을 남기는 방식 우선. **[제안]**
- 대사 시스템: 대사 데이터는 엔진 밖 파일(스프레드시트/JSON)로 관리하고 현지화 키를 처음부터 붙인다(R B.3).
- 동료: **없음(확정, 부록 B 8번)**.

### P2-6. 적·AI
- 적 종류 수는 P1 측정치로 확정. 적 표현은 무기·행동을 과장해 읽기 쉽게(Z 5장, 적 표현 과장).
- NPC 일정은 단순한 시간표 기반(R 7.3 참고). 완전 시뮬레이션(켄쇼식)은 하지 않는다: 혼돈 제어가 어렵다는 개발자 발언(R B.6). **[제안]**

### P2-7. 알파 종료 기준

### 1인 개발 영향 (결정 4·11의 결과, 위험 경고)
- 조사 문서에 1인으로 대형 오픈월드 3D 액션 RPG를 2~3년에 완성한 사례는 없다. 켄쇼는 사실상 1인으로 약 12년(R B.6). 발헤임은 5인으로 얼리 액세스 시작(R B.6). **[근거]**
- 로드맵 5장은 1인일 때 "콘텐츠 목표를 1/3로, 에셋 구매·외주 적극 활용"을 제안했으나 결정 11이 외주·구매를 배제했다. 따라서 **콘텐츠 목표를 1/3 이하로 줄이고 기간을 늘리는 쪽만 남는다.** 두 선택지 중 하나를 P1 종료 게이트에서 다시 정해야 한다: (a) 월드·퀘스트를 더 줄임, (b) 에셋 구매 등 일부 허용. **[제안]**
- 지형 변형(결정 1)은 기술 난도가 높고 저장·스트리밍·충돌·내비게이션 모두에 영향을 준다. 1인이 규칙 시스템(곱셈형 설계)과 동시에 하면 둘 다 얕아질 위험이 있다. **P0 프로토타입 D에서 비용을 실측**하고, 비용이 크면 변형 범위를 줄인다: 전 지형 자유 변형 → 격자 블록 단위 → 지정 구역만 변형 순으로 축소. **[제안]**
- 곱셈형 규칙(원소 조합)은 로드맵 1장 기둥 1이었으나 독자 요소가 지형 변형으로 정해졌으므로, 규칙 수를 **2~3개로 줄여** 지형 변형과 곱한다(예: 물+지형 → 물길 만들기, 무게+지형 → 쌓기). **[제안]**
- 총 기간: 로드맵 3장의 30개월 + 예비 4개월은 3인 기준 **[가정]**이었다. 1인은 각 단계를 1.5배로 보면 약 45~51개월이 된다. 사용자의 "2~3년" 목표(24~36개월)를 넘으므로 **콘텐츠 목표를 줄여 기간을 맞추거나 기간 목표를 늘리는 결정이 P0 종료 시 필요하다.** **[제안, 사용자 결정 필요]**

## 부록 D. 컨셉 문서(`story-concept-2d.md`) 반영

원래 2D(아이소메트릭 픽셀) 생존 크래프팅 RPG로 설계된 컨셉을 3D로 이식한다. 컨셉 문서의 **스포일러(§7 결말 반전)는 게임 안에서 결말 전까지 드러나지 않는다.** 설계 문서·대사 초안·UI에 반전을 암시하는 문구를 쓰지 않는다는 컨셉 문서의 규칙을 그대로 따른다.

### D-1. 컨셉의 절대수칙 4개와 현재 계획의 충돌/정합
| 절대수칙 | 현재 계획과의 관계 | 해소 |
|---|---|---|
| 1 난이도가 너무 어려워서는 안 된다 (조작·전투·진행) | 기존 계획은 엘든 링식 전투를 참고했음 (R 8.3). 충돌 | 전투는 가볍게, 보스 필수 아님, 낮은 난이도 옵션. 소울류 요소(자세 게이지 등)는 도입하지 않음. P0 프로토타입 A의 성공 기준을 "숙달 없이도 이긴다"로 수정 |
| 2 메인스토리에서 벗어나도 즐겁다 / 진행 잠금 없음 | 젤다식 도구 해금과 충돌 | 결정 15: 해금 허용. 단, 해금되는 이동기·도구는 월드 탐험의 보상으로 얻고, 메인 스토리 진행 없이도 얻을 수 있게 한다 |
| 3 저장·불러오기가 자유롭다 | 계획에 세이브 설계가 있음 (P1-8) | 어디서나 저장, 분기 직전 저장으로 양 결말 열람 가능. 세이브 마이그레이션 필수 |
| 4 모든 걸 설명하지 않는다 (조작법 제외) | 환경 안내 기둥과 일치 | 유지. 온보딩은 튜토리얼 통로 방식(글 없이 잔해 6개로 걷기·줍기를 겪게 함)을 3D로 이식 |

### D-2. 장르 비중 (결정 14: 절충)
- 중심 루프: **줍고(파밍) → 쌓이고 → 짓는다(건축)** + 지형 변형(핵심 요소) + 탐험. 컨셉의 "핵심 재미 딱 하나": 파밍한 것이 눈에 보이는 형태로 세계에 남는 것.
- 전투: 들개·불나비·가시뿌리 같은 컨셉의 몬스터 모델을 이식. 대부분 피할 수 있고 영역을 벗어나면 쫓지 않는다. 싸울지 피할지는 플레이어가 고른다.
- 젤다에서 차용하는 것: 지형·랜드마크로 안내, 규칙 조합, 환경 중심 안내. 보스·던전 중심 진행은 줄인다.
- **새 시스템 추가 필요**: 컨셉에는 건축(판자 바닥·벽·문, 실내 판정, 부수기), 제작(재료 6종 + 마력석, 조리법), 채집 숙련도 1~5, 죽음 규칙(재료 절반 손실)이 이미 설계돼 있다. 기존 로드맵에는 없던 시스템이므로 **P1 슬라이스 범위에 포함**하고 제작 단가를 실측한다.
- **리스크 (신규)**: 지형 변형과 건축의 상호작용. 건물 밑 지형을 깎으면? 변형 불가 영역은 어떻게 표시? P0 프로토타입 D에서 "건축물이 있는 칸의 지형 변형 규칙"을 함께 검증한다. **[제안]**

### D-4. 서브스토리·결말 (결정 18·19)
- 여주인공 포지션 NPC 2명. 컨셉의 죽음 방식 세 가지(갑작스러운 사고 / 서서히 알면서도 못 막음 / 주인공을 지키다가) 중 2가지를 고른다. 컨셉에는 "셋째는 알면서도 진행해 죄책감이 재료"라는 설계가 있어, 2명이면 그 효과를 어떻게 살릴지 별도 결정이 필요하다.
- "한 명은 주인공이 원인임을 어렴풋이 눈치채고 죽음" 규칙은 유지한다.
- 인연 수치는 플레이어에게 숨긴다 (UI 표시 금지). 텔레메트리/디버그 UI에서만 확인.
- 서브스토리 경고 없음, 세이브 제한 없음.
- 죽는 NPC는 대체 불가능한 기능(유일한 상인 등)에 묶지 않는다.
- 결말은 마지막 에피소드의 선택지 한 곳에서만 분기, 2갈래. 그전까지는 분기 없음.

### D-6. 곱셈형 규칙 (확정: 결정 20·21)
**결정 20: 규칙은 마소 · 물 · 불 3개** (+ 핵심 요소인 지형 변형). 무게/중력은 제외한다.
**결정 21: 마소 농도가 지형 변형의 범위와 내구를 정한다.**

규칙 수 상한(로드맵 6장 "4개 내외")을 지켰다. 이 3개 규칙 + 지형 변형 = 4개 축의 조합이므로 조합표는 6칸(아래)이다.

#### 규칙 정의 **[제안, 아래는 초안이며 P0 프로토타입 B/D에서 수정]**
| 규칙 | 상태값 | 세계에서의 모습 | 컨셉 연결 |
|---|---|---|---|
| 마소 | 지역 농도(연속값), 몸에 쌓인 양(플레이어) | 지역별 농도 차(시가지 옅음 → 경계지·요정숲 짙음), 마력석, 마력석 등, 3 이상이면 몸이 빛남 | 컨셉 2-3, [구현] 8차 |
| 물 | 있음/없음, 흐름 방향, 깊이 | 물길, 웅덩이, 비 | 컨셉에 없음. 신규 |
| 불 | 불붙음/안 붙음, 연료 | 점화, 연소, 빛 | 불나비, 가시뿌리 연결 후보 |

#### 조합 매트릭스 초안 **[제안]**
| | 지형 변형 | 마소 | 물 | 불 |
|---|---|---|---|---|
| **지형 변형** | — | 농도가 변형 범위·내구를 결정(결정 21). 옅은 곳은 작게·쉽게 무너지고, 짙은 곳은 크게·오래 유지 | 판 땅이 물길을 바꿈. 파면 물이 고이고, 쌓으면 막힘 | 불이 번지는 길을 지형으로 끊음(방화선) |
| **마소** | | — | 마소가 짙은 물은 빛남/약효(후보, 미확정) | 마소 짙은 곳에서 불이 더 강하거나 오래감(후보) |
| **물** | | | — | 물이 불을 끔. 젖은 연료는 불이 안 붙음 |
| **불** | | | | — |
- "후보"는 아직 결정하지 않은 칸. 의도 없는 칸은 "정의 안 함"으로 표기한다(TotK의 조합 하나하나 조정 방식, Z 3.12).
- **지형 변형 × 마소**가 이 게임의 독자 조합이다. 이 칸이 재미있는지 P0 프로토타입 D에서 가장 먼저 검증한다.

#### 구현 주의 **[제안, 미검증]**
- 물은 구현 비용이 가장 큰 규칙이다. 유체 시뮬레이션이 아니라 **격자 위 물 높이/흐름 규칙**(타일 단위 단순 규칙)으로 제한하는 안을 기본으로 둔다. 저폴리곤 화풍과도 맞는다. 이 방식의 구현 난이도는 조사에 없으므로 프로토타입으로 확인한다.
- 불은 타일/오브젝트 속성 기반 전파(연료 속성)로 둔다.
- 마소는 지역 농도 맵(저해상도 격자) + 플레이어 보유량으로 둔다. 마소 농도는 지형 변형 입력이므로 변형 지형 델타 저장과 함께 세이브된다.
- 규칙은 데이터 표(속성 태그 + 상태 + 자극 → 결과)로 정의한다(P0-3 B).
- 물 × 지형 변형이 기술적으로 감당 불가면 물을 빼고 마소·불 2개로 줄인다. 이 퇴로를 P0 종료 게이트에 명시한다.

### D-7. 카메라 (확정: 결정 22·23)
- **결정 22: 3인칭 추격 카메라.** 컨셉의 아이소메트릭은 계승하지 않는다. 이유: 젤다식 삼각형 규칙·랜드마크 빵 부스러기·시선 유도(Z 3.11)가 눈높이 시야에 의존한다.
- **결정 23: 실내는 반투명/커트어웨이.** 플레이어가 실내에 들어가면 지붕과 시야를 가리는 벽이 페이드아웃한다. 별도 로드 공간은 쓰지 않는다. 실내 판정(문을 포함해 벽으로 둘러싼 칸)은 컨셉 4-3의 규칙을 이식한다.
- 비용 **[제안]**: 추격 카메라는 (1) 지형·건축물과의 충돌, (2) 지형 변형으로 지형이 바뀐 직후 카메라 위치 보정, (3) 좁은 실내에서의 카메라, (4) 락온/주목 카메라가 모두 추가 작업이다. P0 프로토타입 A·C·D에서 이 네 가지를 같이 검증한다.
- 퇴로 **[제안]**: P0 종료 게이트에서 추격 카메라 비용이 과도하면 **쿼터뷰 3D(고정각)로 후퇴**한다. 후퇴 시 젤다식 랜드마크 기법의 비중을 줄이고 지형 변형·건축 중심으로 재설계한다. 이 후퇴는 사용자 승인 후에만 한다.

### D-8. 예산과 투입 시간 (확정: 결정 24~26)
- **결정 24: 투입 시간은 파트타임, 주 20~30시간.**
- **결정 25: 자금은 자비(저축·현재 수입)로만.** 외부 투자, 지원사업, 크라우드펀딩을 쓰지 않는다. 마케팅 일정을 앞당길 필요가 없다.
- **결정 26: 수익은 보너스, 완성이 목표.** 가격·마케팅 최적화에 개발 시간을 쓰지 않는다. 출시 후 3개월 계획(P4)은 유지하되 확장 콘텐츠(드워프 마을·마경)는 수익과 무관하게 여력이 될 때 추진한다.

- 한 번에 몰아서 못 하는 파트타임은 맥락 전환 비용 때문에 위 환산보다 더 느려질 수 있다. 조사 문서에 근거는 없다.
- 이는 사용자가 처음 말한 24~36개월 목표를 크게 넘는다. 아래 중 하나 이상을 P0 종료 게이트에서 정해야 한다. **[제안, 사용자 결정 필요]**
  1. **1.0 범위 축소**: 4지역 → 시가지+경계지+튜토리얼 통로 2~3지역, 던전 1개, 여주인공 서브스토리 2개 유지 여부 재검토.
  2. **단계적 출시**: 1.0은 코어 루프(파밍·건축·지형 변형)와 첫 지역 위주로 내고 요정숲·던전을 업데이트로 추가. 단 "얼리 액세스 없음"(결정 7), "출시 전 약속 관리"(R 15.2)와 충돌 가능.
  3. **기간 목표 변경**: 5~8년을 전제로 일정 재설정. 번아웃·모티베이션 위험이 커진다(R 14.5-4, B.6 켄쇼 사례).
  4. **에셋 구매 허용**: 결정 11("전부 직접 제작")을 수정하는 안. 기간을 가장 크게 줄이는 수단.

**결정 27: 위 1~4 중 선택은 P0 프로토타입 결과를 본 뒤에 정한다.** 판단 입력은 프로토타입 D(지형 변형)·B(규칙)·카메라 비용 실측과 P0 4주차 엔진 게이트 결과다. 그때까지 범위는 현 결정(4지역, 전부 직접 제작)을 유지한다.
