## P0. 프리프로덕션 (3개월)

### P0-1. 목표
기둥(로드맵 1장)을 실제 조작으로 검증하고, 엔진과 스코프의 큰 방향을 정한다. 아트·콘텐츠 제작은 하지 않는다.

### P0-2. 작업 목록

| 주차 | 작업 | 산출물 |
|---|---|---|
| 1 | 엔진 라이선스·지형·스트리밍 사례를 공식 문서로 확인, 개발 환경·버전관리(대용량 에셋 지원)·빌드 자동화 구성 | 엔진 비교 메모, 레포 구조 |
| 1~4 | **엔진 게이트**: 스트리밍 테스트 월드(저폴리곤 지형+식생 인스턴싱), 최저사양 기기 측정 | 프레임타임 그래프, 판정 |
| 2~6 | 프로토타입 A **전투 감**: 이동, 회피, 주목 카메라, 공격 1종, 적 1종 | 플레이 가능 빌드 |
| 3~8 | 프로토타입 B **규칙 상호작용**: 원소/물리 규칙 2~3개의 조합 | 조합 매트릭스 표, 데모 룸 |

| 6~10 | 화풍 실험: 저폴리곤 팔레트·조명·포스트프로세싱·VFX 스타일 3안 | 화풍 가이드 초안 |

| 12 | 스코프 가안, 컷 회의 | 콘텐츠 목표 가안 |

### P0-3. 프로토타입 상세

**A. 전투 감 (R 8.1~8.3, Z 5장 "적 표현 과장")**
- 필수: 입력 버퍼, 선행 입력 취소 창 규칙, 히트스톱, 카메라 흔들림, 피격 반응, 적 예비동작 가독성.
- 선택 검토: 자세(posture) 게이지(세키로, R 8.3)와 스태미나 중 하나만 선택. 둘 다 넣지 않는다. **[제안]**
- 무기 내구도: **없음(확정, 부록 B 9번)**. 근거: Z 7장에서 BotW 내구도가 전투 흐름을 끊는다는 비판.
- 수치: 이동속도, 회피 무적 프레임, 공격 선딜/후딜은 **[측정]**(플레이테스트로 조정). 임의 초기값은 코드가 아니라 데이터 테이블에 둔다.
- 성공 기준: 처음 해보는 테스터 5명 중 4명이 설명 없이 회피·공격·주목을 사용하고, 같은 적과 3번 반복해도 지루하다고 하지 않는다. **[가정]**

**B. 규칙 상호작용 (곱셈형 설계, Z 3.11, 5장)**
- 규칙 후보(4개 이내 **[가정]**): 불(점화·연소), 물(젖음·전도·부력), 바람(운반·확산), 무게(누름·부력).
- 구현 방식 **[제안]**: 오브젝트가 **속성 태그**와 **상태**를 갖고, 규칙은 "태그+상태+자극 → 결과" 표(데이터)로 정의한다. 규칙 추가가 코드 수정 없이 표 수정이 되게 한다.
- 조합 매트릭스: 규칙×오브젝트 종류 표를 문서로 관리하고, 각 칸에 의도한 결과 또는 "정의 안 함"을 적는다(TotK는 조합을 하나하나 손으로 조정, Z 3.12).
- 제어 가능성: 창발은 통제 가능한 범위에서 시작한다(R 7.4). 규칙 수가 늘면 자동 시뮬레이션 테스트로 결함을 잡는다.
- 성공 기준: 퍼즐용 전용 오브젝트 없이 규칙만으로 서로 다른 해법이 2개 이상인 데모 상황 3개를 만들 수 있다. **[가정]**

**C. 이동 (R 4.1, Z 7장)**
- 이동기가 월드 체감 크기와 탐험 동기를 만든다(R 4.1). 반대로 강한 이동 도구는 탐험을 잠식한다(Z 7장 TotK 탈것).
- P0에서는 달리기+점프+오르기(스태미나 소모)부터. 활공·탈것은 슬라이스에서 판단.
- 성공 기준: 지형만 보고 "저 봉우리까지 오르고 싶다"가 테스터 발언으로 나온다.

**D. 지형 변형 (결정 1, 독자 핵심 요소)** — 상세 사양(2D 개정판): `prototype-d-spec.md`
- 질문: 플레이어가 땅을 쌓고 깎을 때 (1) 입력 지연, (2) 변형 결과의 저장 크기, (3) 스트리밍 경계에서의 일관성, (4) 충돌·내비게이션 갱신 비용이 어느 정도인가.
- 구현 후보 **[제안, 미검증]**: 높이맵 편집(단순, 동굴·오버행 불가), 복셀/청크 지형(자유도 높음, 메모리·메시 생성 비용 큼), 격자 블록(저폴리곤 화풍과 잘 맞고 구현 쉬움). 후보별 비용은 조사에 없으므로 실측한다.
- 저장: 원본 지형은 읽기 전용, 변형은 **차이(델타)만 세이브에 저장**하는 구조를 기본안으로 시험한다. **[제안]**
- 젤다식 퍼즐과 연결: 지형 변형이 해법이 되는 퍼즐 데모 3개(다리 만들기, 물길 돌리기, 벽 쌓아 오르기).
- 성공 기준: 최저사양에서 변형 중 30fps 유지, 변형 100곳 저장·불러오기 후 세이브 용량 증가량이 목표(**[측정]**) 이내, 스트리밍 경계에서 틈·튕김 없음. **[가정]**
- 실패 시 변형 범위를 축소(부록 B의 1인 개발 영향).

### P0-4. 엔진 게이트 상세
- 테스트 월드: 8~16km² **[가정]** 지형, 식생 인스턴싱, 저폴리곤 건물 더미. 구체 면적은 목표 월드 크기 가안(P0 종료)보다 크게 잡아 여유를 확인한다.
- 측정 항목: 평균/99퍼센타일 프레임타임, 이동 중 히치 횟수, 메모리, 디스크 용량, 스트리밍 반경과 로딩 지연, 빌드 시간.
- 판정은 로드맵 2장 기준. 못 통과 시 대안 순서는 로드맵 2장.
- 참고: Unreal의 월드 파티션은 셀 단위 스트리밍(예시 셀 256m, 로딩 범위 768m는 **문서의 예시값**)을 공식 제공한다(R 18.4). Unity/Godot를 쓰면 이에 해당하는 시스템을 직접 만든다고 가정하고 일정에 반영한다. **[가정]**

## P1. 수직 슬라이스 (6개월)

### P1-1. 목표
한 지역을 **출시 품질**로 완성해 (1) 재미를 재확인하고 (2) 콘텐츠 1단위당 제작 시간을 실측한다(R 14.3: 슬라이스는 데모가 아니라 파이프라인 측정 도구). 폴리싱된 슬라이스가 미해결 문제를 가릴 수 있다는 경고(R 14.3, C)가 있으므로 **최저사양 기기에서 항상 돌려 본다**(R 14.4).

### P1-2. 슬라이스 범위 **[가정]**
- 지역 1개(예: 1~2km²), 거점(마을) 1개, 필드 POI 15~25개, 소형 던전 1개, 보스 1개, 주요 퀘스트 1줄 + 사이드 퀘스트 3개, 이동기 2~3개 해금.
- 플레이 시간 목표 30~60분.
- 슬라이스에 넣는 이유: 스카이림식 이동(산이 직선 이동을 막음, R 4.1), BotW식 삼각형 규칙(Z 3.11), 엘든 링식 "보스 먼저 놓고 지형을 맞춤"(R 4.5)을 한 지역에서 모두 시험한다.

### P1-3. 월드 사양

**지형 제작 방식 [제안]**: 완전 절차 생성이 아닌 **수작업 큰 틀 + 도구 보조 산포**. 근거: 젤다류는 랜드마크 배치가 핵심이고(Z 3.11), 규칙 기반 산포는 편집 가능해야 한다(R 4.6 호라이즌 사례: 아티스트가 규칙을 수정 가능).
1. 큰 틀: 핵심 지점(보스, 마을, 던전 입구, 대형 랜드마크)을 먼저 배치(R 4.5).
2. 지형 조형: 삼각형 규칙(큰 삼각형=랜드마크, 중간=경로 차폐, 작은 것=속도 조절, Z 3.11)에 맞춰 산·능선·계곡 구성.
3. 산포: 식생·바위·소품은 규칙 기반 도구로 배치 후 수작업 보정.
4. POI: 자원·적·보상을 미니 클러스터로 묶는다(R 4.2, 18.3 Luban 2부: 자원은 흩뿌리지 말고 POI에 묶는다).

**POI 규칙 [제안]**
- 어디서나 지평선에 성격이 다른 POI가 최소 3개 보이게(R 4.2 "다양성 규칙", C라 검증 필요).
- 각 POI는 명확한 보상 1개(BotW 사례: 사당→체력/스태미나, 적 진지→무기, 마구간→회복·상점, 18.3 GMTK 요약).
- 이동 간격: 60~120초(R 4.2, 단일 블로그 경험칙, **[측정]** 필수). 슬라이스에서 실제 이동 속도로 간격을 재서 확정한다.
- 소형 랜드마크도 멀리서 읽혀야 한다(사당 발광, 연기, 특징적 바위, 18.3 GMTK 요약). 저폴리곤이라 **실루엣과 색**으로 구분한다. **[제안]**
- 건너뛰는 구역은 플레이테스트로 찾아 은은한 표지를 추가(Z 3.11).

**레벨 디자인 문법 [제안]** (R 18.3 Luban 3부): 자원 배치 규칙(예: 특정 식물은 특정 환경에만), 등반·통과 가능한 면의 시각 단서, 문 폭·점프 높이 등 크기 표준 템플릿을 문서로 고정한다.

### P1-4. 전투·성장 사양
- 적 3~5종 + 보스 1. 적마다 서로 다른 규칙 반응(불에 약함 등)을 부여해 곱셈형 규칙과 연결.
- 보스: 월드에 먼저 배치하고 지형을 맞춤(R 4.5). 보스가 이동기/도구를 준다(발헤임·젤다의 보스 보상, R B.6).
- 성장: 슬라이스에서는 **능력 해금 중심**(이동기, 도구), 수치 성장은 최소(R 9.4, Z 아이템 게이팅). 레벨 스케일링은 **쓰지 않는다**(지역 고정 위험도, R 9.1 [제안]).
- 장비 요구 조건을 사후에 올리지 않는다(R 9.1 위쳐 3 패치 사례의 교훈).

### P1-5. 퀘스트·서사 사양
- 메인 1줄 + 사이드 3개. 사이드마다 감정·장소·메카닉이 달라야 한다(R 5.3). 수집·배달 최소화.
- 퀘스트 제작 파이프라인: 피치→폐기→초안→임시 에셋 구현(R 5.3). **슬라이스에서 한 퀘스트를 만드는 데 걸린 시간·인원·폐기율을 기록**한다. 이 값이 P2 스코프 계산 입력이다.
- 서사 원칙 후보(R 18.3 Sasko, 기사 요약): 불필요한 반복 설명 제거, 정보는 집중된 순간에, 설명은 환경으로, 선택의 결과는 플레이어에게 보이게. 사이드는 필러가 아니라 세계/인물을 드러내야 함.
- 대사량·현지화는 R B.3 참고(비용 수치는 미확인). 한국어 우선, 외 언어는 P3 이전에 결정.

### P1-6. UI·내비게이션·온보딩
- 지도: 기본은 **마커 최소**(환경이 안내). 가이드 모드 옵션으로 마커 밀도를 올릴 수 있게(R 11.1 [제안], Z 수칙 1).
- 나침반: 추적 퀘스트와 플레이어 웨이포인트는 항상, 그 외는 반경 내에서만(R 11.1, C).
- 온보딩: 첫 10분 안에 이동·전투·규칙 상호작용 1개를 체험시키되 튜토리얼은 스킵 가능(Z 7장 피 튜토리얼 비판). 숙달감·목적감·몰입감(R 11.2).
- 접근성: 키 리매핑, 자막 크기, 색약 대응, 난이도 옵션 초안을 슬라이스에서 구현(처음부터 계획해야 가능, R 11.3).

### P1-7. 사운드
- 환경음 중심, BGM 절제(Z 3.11, R 12). 전투/탐험/마을 3종 음악 레이어를 먼저 만들고 스템 전환 구조를 적용(R 12 RDR2 사례 방식은 규모가 달라 축소 적용). **[제안]**

### P1-8. 기술 사양
- 스트리밍: P0에서 검증한 방식을 슬라이스에서 실콘텐츠로 재측정.
- 데이터 중심: 아이템·적·퀘스트·규칙표를 데이터 파일로 분리, 이후 모드/에디터 공개 가능성을 열어 둔다(R 17.6).
- 세이브: 버전 필드와 마이그레이션 훅을 처음부터 둔다. **[제안]**
- 자동화: 빌드 서버, 스모크 테스트(맵 순회 봇), 규칙 조합 자동 테스트.
- 계측: 플레이 위치 히트맵, 이탈 지점, 사망 지점 로그(플레이테스트용).

## P2. 콘텐츠 제작 / 알파 (10개월)

### P2-1. 목표
확정된 스코프만큼 월드·던전·퀘스트·적·시스템을 만든다. 마지막에 **엔딩까지 거친 상태로 플레이 가능**해야 한다.

### P2-2. 제작 순서 **[제안]**
1. 월드 골격: 전체 지형, 거점, 핵심 지점(보스·던전 입구) 배치(R 4.5).
2. 메인 퀘스트 한 줄 관통(순서 고정 구간은 첫 구간만, R 18.3 Luban 2부 "첫 클러스터는 온보딩").
3. 던전·보스를 진행 순서대로(이동기/도구 해금 흐름과 동기화).
4. 필드 POI 채움: 지역별로 변주 확보(Z 수칙 9: 새 지역마다 다른 규칙·위협·보상).
5. 사이드 퀘스트: 폐기율을 감안해 확정 수의 1.3~1.5배 피치 **[가정]**(R 14.5-2 "폐기 비율을 제작비에 반영").
6. 경제·상점·루팅.
7. 사운드·음악 본제작.

### P2-3. 월드 구성 규칙 **[제안]**
- 지역 수 3~5개 **[가정]**, 지역마다 고유한 (1) 위협 (2) 자원 (3) 환경 규칙(예: 추위, 독, 습도)을 둔다. 새 지역이 시각만 다르면 실패(R 18.3 Luban 2부, Z 7장 "지역 단조로움").
- 지형 규칙: 이동 차단은 임의 장벽이 아닌 게임플레이 조건(도구·환경 조건)으로(Luban 2부, 파크라이 프라이멀의 추위 사례).
- 손으로 만든 "정수" 구역(레거시 던전급, R 17.2)을 정하고 예산을 집중한다. 나머지는 도구 보조.
- 빠른 이동: 도입 시 비용·제한을 둔다(발헤임 포털의 "광석 불가" 사례, R B.6 [근거, 해석은 C]).
- 하늘/지하 같은 수직 확장은 슬라이스에서 효과가 입증될 때만. 입증 전에는 후보에서 제외. **[제안]**

### P2-4. 전투·성장·경제
- 성장 축 2개(능력 해금 + 소량 수치/빌드). 스킬 트리를 쓰면 노드는 새 선택지를 열어야 하고 +%만 쌓는 필러를 피한다(R 17.4, 18.5 스카이림 퍽 비판).
- 스탯 스케일링을 쓴다면 체감 곡선을 표로 설계하고 체감 구간(초반 급상승→완만)을 목표 곡선으로 먼저 그린다(엘든 링 스케일링 곡선 사례, R 18.4 [근거 C]).
- 경제: 시작 전에 수입 총량 대비 예상 지출을 계산하고 실제 플레이로 비교(R 18.5 슈워츠 요약), 영구 업그레이드 대신 일시 소모품 활용, 화폐 종류를 옆으로 확장(요약 내용, 원문 미확인). **[제안]**
- 유료 랜덤 요소(확률형)는 두지 않는다(로드맵 6장).

### P2-5. 퀘스트·서사
- 목표 수치 **[가정]**: 메인 1줄(8~12 구간), 사이드 20~30개(폐기 전 30~45개 피치), 거점 NPC 15~25명. 이 숫자는 P1 측정값이 나오면 교체한다.
- 제작 규칙: 퀘스트 설계서 1쪽(감정/장소/메카닉/보상/실패 조건), 퀘스트마다 서로 다른 점을 한 줄로 쓴다(R 5.3).
- 선택·결과: 결과는 지연돼도 플레이어에게 보이게(Sasko 10가지 교훈 기사 요약, R 18.3). 분기는 최소로, 변수로 흔적을 남기는 방식 우선. **[제안]**
- 대사 시스템: 대사 데이터는 엔진 밖 파일(스프레드시트/JSON)로 관리하고 현지화 키를 처음부터 붙인다(R B.3).
- 동료: **없음(확정, 부록 B 8번)**.

### P2-6. 적·AI
- 적 종류 수는 P1 측정치로 확정. 적 표현은 무기·행동을 과장해 읽기 쉽게(Z 5장, 적 표현 과장).
- NPC 일정은 단순한 시간표 기반(R 7.3 참고). 완전 시뮬레이션(켄쇼식)은 하지 않는다: 혼돈 제어가 어렵다는 개발자 발언(R B.6). **[제안]**

### P2-7. 알파 종료 기준
- [ ] 시작부터 엔딩까지 플레이 가능
- [ ] 콘텐츠 완성도 자체는 거칠어도 되지만 차단 버그(진행 불가)는 월 단위 목록으로 관리
- [ ] 컷 목록 확정(기능 동결 후보)
- [ ] 최저사양 프레임 목표의 90% 이상 **[가정]**
- [ ] 퀘스트·던전 폐기 후에도 P1 계획 대비 일정 편차 20% 이내 **[가정]**, 초과 시 컷 회의

### P2-8. 얼리 액세스 결정 (P2 6개월차)
조건 참고(R B.9, B.6):
- 장점: 자금·피드백, 발헤임은 5인 팀이 얼리 액세스로 성공.
- 위험: 불안한 출시가 평판·재정에 치명적. 스팀은 수익 창출 목적만으로 쓰지 말라고 경고. 싱글 플레이 RPG 사례는 R에 없음(C).

## 부록 A. 시스템 의존 관계 (제안)

```
규칙표(속성/상태) ──┬─> 전투(적 약점) ──> 보스 ──> 이동기/도구 해금 ──> 월드 게이팅
```

### 1인 개발 영향 (결정 4·11의 결과, 위험 경고)
- 조사 문서에 1인으로 대형 오픈월드 3D 액션 RPG를 2~3년에 완성한 사례는 없다. 켄쇼는 사실상 1인으로 약 12년(R B.6). 발헤임은 5인으로 얼리 액세스 시작(R B.6). **[근거]**
- 로드맵 5장은 1인일 때 "콘텐츠 목표를 1/3로, 에셋 구매·외주 적극 활용"을 제안했으나 결정 11이 외주·구매를 배제했다. 따라서 **콘텐츠 목표를 1/3 이하로 줄이고 기간을 늘리는 쪽만 남는다.** 두 선택지 중 하나를 P1 종료 게이트에서 다시 정해야 한다: (a) 월드·퀘스트를 더 줄임, (b) 에셋 구매 등 일부 허용. **[제안]**
- 지형 변형(결정 1)은 기술 난도가 높고 저장·스트리밍·충돌·내비게이션 모두에 영향을 준다. 1인이 규칙 시스템(곱셈형 설계)과 동시에 하면 둘 다 얕아질 위험이 있다. **P0 프로토타입 D에서 비용을 실측**하고, 비용이 크면 변형 범위를 줄인다: 전 지형 자유 변형 → 격자 블록 단위 → 지정 구역만 변형 순으로 축소. **[제안]**
- 곱셈형 규칙(원소 조합)은 로드맵 1장 기둥 1이었으나 독자 요소가 지형 변형으로 정해졌으므로, 규칙 수를 **2~3개로 줄여** 지형 변형과 곱한다(예: 물+지형 → 물길 만들기, 무게+지형 → 쌓기). **[제안]**
- 총 기간: 로드맵 3장의 30개월 + 예비 4개월은 3인 기준 **[가정]**이었다. 1인은 각 단계를 1.5배로 보면 약 45~51개월이 된다. 사용자의 "2~3년" 목표(24~36개월)를 넘으므로 **콘텐츠 목표를 줄여 기간을 맞추거나 기간 목표를 늘리는 결정이 P0 종료 시 필요하다.** **[제안, 사용자 결정 필요]**

## 부록 D. 컨셉 문서(`story-concept-2d.md`) 반영

원래 2D(아이소메트릭 픽셀) 생존 크래프팅 RPG로 설계된 컨셉을 3D로 이식한다. 컨셉 문서의 **스포일러(§7 결말 반전)는 게임 안에서 결말 전까지 드러나지 않는다.** 설계 문서·대사 초안·UI에 반전을 암시하는 문구를 쓰지 않는다는 컨셉 문서의 규칙을 그대로 따른다.

### D-2. 장르 비중 (결정 14: 절충)
- 중심 루프: **줍고(파밍) → 쌓이고 → 짓는다(건축)** + 지형 변형(핵심 요소) + 탐험. 컨셉의 "핵심 재미 딱 하나": 파밍한 것이 눈에 보이는 형태로 세계에 남는 것.
- 전투: 들개·불나비·가시뿌리 같은 컨셉의 몬스터 모델을 이식. 대부분 피할 수 있고 영역을 벗어나면 쫓지 않는다. 싸울지 피할지는 플레이어가 고른다.
- 젤다에서 차용하는 것: 지형·랜드마크로 안내, 규칙 조합, 환경 중심 안내. 보스·던전 중심 진행은 줄인다.
- **새 시스템 추가 필요**: 컨셉에는 건축(판자 바닥·벽·문, 실내 판정, 부수기), 제작(재료 6종 + 마력석, 조리법), 채집 숙련도 1~5, 죽음 규칙(재료 절반 손실)이 이미 설계돼 있다. 기존 로드맵에는 없던 시스템이므로 **P1 슬라이스 범위에 포함**하고 제작 단가를 실측한다.
- **리스크 (신규)**: 지형 변형과 건축의 상호작용. 건물 밑 지형을 깎으면? 변형 불가 영역은 어떻게 표시? P0 프로토타입 D에서 "건축물이 있는 칸의 지형 변형 규칙"을 함께 검증한다. **[제안]**

### D-4. 서브스토리·결말 (결정 18·19)
- 여주인공 포지션 NPC 2명. 컨셉의 죽음 방식 세 가지(갑작스러운 사고 / 서서히 알면서도 못 막음 / 주인공을 지키다가) 중 2가지를 고른다. 컨셉에는 "셋째는 알면서도 진행해 죄책감이 재료"라는 설계가 있어, 2명이면 그 효과를 어떻게 살릴지 별도 결정이 필요하다.
- "한 명은 주인공이 원인임을 어렴풋이 눈치채고 죽음" 규칙은 유지한다.
- 인연 수치는 플레이어에게 숨긴다 (UI 표시 금지). 텔레메트리/디버그 UI에서만 확인.
- 서브스토리 경고 없음, 세이브 제한 없음.
- 죽는 NPC는 대체 불가능한 기능(유일한 상인 등)에 묶지 않는다.
- 결말은 마지막 에피소드의 선택지 한 곳에서만 분기, 2갈래. 그전까지는 분기 없음.

### D-6. 곱셈형 규칙 (확정: 결정 20·21)
**결정 20: 규칙은 마소 · 물 · 불 3개** (+ 핵심 요소인 지형 변형). 무게/중력은 제외한다.
**결정 21: 마소 농도가 지형 변형의 범위와 내구를 정한다.**

규칙 수 상한(로드맵 6장 "4개 내외")을 지켰다. 이 3개 규칙 + 지형 변형 = 4개 축의 조합이므로 조합표는 6칸(아래)이다.

#### 규칙 정의 **[제안, 아래는 초안이며 P0 프로토타입 B/D에서 수정]**
| 규칙 | 상태값 | 세계에서의 모습 | 컨셉 연결 |
|---|---|---|---|
| 마소 | 지역 농도(연속값), 몸에 쌓인 양(플레이어) | 지역별 농도 차(시가지 옅음 → 경계지·요정숲 짙음), 마력석, 마력석 등, 3 이상이면 몸이 빛남 | 컨셉 2-3, [구현] 8차 |
| 물 | 있음/없음, 흐름 방향, 깊이 | 물길, 웅덩이, 비 | 컨셉에 없음. 신규 |
| 불 | 불붙음/안 붙음, 연료 | 점화, 연소, 빛 | 불나비, 가시뿌리 연결 후보 |

#### 조합 매트릭스 초안 **[제안]**
| | 지형 변형 | 마소 | 물 | 불 |
|---|---|---|---|---|

- "후보"는 아직 결정하지 않은 칸. 의도 없는 칸은 "정의 안 함"으로 표기한다(TotK의 조합 하나하나 조정 방식, Z 3.12).

#### 구현 주의 **[제안, 미검증]**
- 물은 구현 비용이 가장 큰 규칙이다. 유체 시뮬레이션이 아니라 **격자 위 물 높이/흐름 규칙**(타일 단위 단순 규칙)으로 제한하는 안을 기본으로 둔다. 저폴리곤 화풍과도 맞는다. 이 방식의 구현 난이도는 조사에 없으므로 프로토타입으로 확인한다.
- 불은 타일/오브젝트 속성 기반 전파(연료 속성)로 둔다.
- 마소는 지역 농도 맵(저해상도 격자) + 플레이어 보유량으로 둔다. 마소 농도는 지형 변형 입력이므로 변형 지형 델타 저장과 함께 세이브된다.
- 규칙은 데이터 표(속성 태그 + 상태 + 자극 → 결과)로 정의한다(P0-3 B).
- 물 × 지형 변형이 기술적으로 감당 불가면 물을 빼고 마소·불 2개로 줄인다. 이 퇴로를 P0 종료 게이트에 명시한다.

### D-7. 카메라 (확정: 결정 22·23)
- **결정 22: 3인칭 추격 카메라.** 컨셉의 아이소메트릭은 계승하지 않는다. 이유: 젤다식 삼각형 규칙·랜드마크 빵 부스러기·시선 유도(Z 3.11)가 눈높이 시야에 의존한다.
- **결정 23: 실내는 반투명/커트어웨이.** 플레이어가 실내에 들어가면 지붕과 시야를 가리는 벽이 페이드아웃한다. 별도 로드 공간은 쓰지 않는다. 실내 판정(문을 포함해 벽으로 둘러싼 칸)은 컨셉 4-3의 규칙을 이식한다.
- 비용 **[제안]**: 추격 카메라는 (1) 지형·건축물과의 충돌, (2) 지형 변형으로 지형이 바뀐 직후 카메라 위치 보정, (3) 좁은 실내에서의 카메라, (4) 락온/주목 카메라가 모두 추가 작업이다. P0 프로토타입 A·C·D에서 이 네 가지를 같이 검증한다.
- 퇴로 **[제안]**: P0 종료 게이트에서 추격 카메라 비용이 과도하면 **쿼터뷰 3D(고정각)로 후퇴**한다. 후퇴 시 젤다식 랜드마크 기법의 비중을 줄이고 지형 변형·건축 중심으로 재설계한다. 이 후퇴는 사용자 승인 후에만 한다.

### D-9. 여주인공 포지션 NPC 2명 (확정: 결정 28~30)
> 스포일러 주의: 컨셉 §7의 반전과 연결되는 설계 메모다. 게임 안 대사·아이템 설명에는 쓰지 않는다.

- **결정 28: 죽는 방식은 "우연 사고"와 "서서히 알면서도 못 막음".** 컨셉의 "지키다가"는 쓰지 않는다. 따라서 컨셉의 셋째("알면서도 진행해 죄책감이 재료") 효과는 둘째 인물이 맡는다.
- **결정 29: 첫째 인물 = 시가지, 전직 간호사. 하려던 일: 체육관 대피소로 사람들을 모으는 것.**
- **결정 30: 둘째 인물 = 경계(잘라낸 자리·경계선)를 연구하는 사람.** 사용자 제안. 세부 직업(측량, 지도 제작, 기록 등)은 미정.

| | 첫째 | 둘째 |
|---|---|---|
| 이름 | **Enil(에닐)** — line을 거꾸로 쓴 것. 선으로 이어져 있다는 뜻을 암시. 사용자 작명(결정 38) | **Mio(미오)** — 물망초 학명(Myosotis)에서 땀. 사용자 작명(결정 39), 영문 표기 Mio(결정 40) |

#### 설계 제약 (컨셉 §6에서 가져옴)
- 서브스토리 1개당 결말 1개, 분기 없음. 인연 수치는 숨기고 말투·방문·건네는 것으로만 드러낸다.
- 어느 쪽도 대체 불가능한 기능(유일한 상인·대장장이 등)에 묶지 않는다. 첫째의 대피소는 "모으려 한 일"이지 플레이어에게 필수인 서비스가 아니다.
- 연애만 하는 인물이 아니라 각자 하려던 일이 있어야 한다.
- 첫째의 사고는 우연이어야 하므로 몬스터·적대적 존재 때문에 죽지 않게 한다. **[제안]**
- 둘째의 "서서히 알면서도 못 막음"은 플레이어가 신호를 알아볼 수 있어야 한다. 사인(병·부상·경계 현상 등)은 미정이며, 기존 마소 설정(몸에 쌓을수록 마력이 강해짐)과 모순되지 않게 정해야 한다.
- 경계 연구자라는 직업은 컨셉의 핵심 장소(잘라낸 자리)를 보는 시선을 제공하므로, 지형 변형(핵심 요소)과 연결해 서브스토리 퀘스트의 메카닉으로 쓸 수 있다. **[제안, 미결정]**

### D-10. 요정 NPC 말투 (확정: 결정 31~33)
- **결정 31: 결은 "시큰둥하고 돌려 말한다".** 관심 없는 척하지만 정보를 아예 안 주는 것은 아니고 한 번 비틀어 말한다. 컨셉의 "적대적이지 않지만 친절하지도 않다" 방향.
- **결정 32: 반말.**
- **결정 33: 주인공을 알아보는 듯한 반응을 아주 은근히 넣는다** (컨셉 §7 복선 후보 3번). 결말 전에는 다르게 읽혀야 하고 게임은 설명하지 않는다.

기존 NPC와의 구분 **[제안]**
| | 노인 | 낯선 사람 | 요정 |
|---|---|---|---|
| 결 | 길고 담담 | 짧게 끊김 | 시큰둥, 돌려 말함 |
| 화법 | 설명하듯 | 방어적 | 대답이 한 단 비틀려 있음 |

초안 대사 (**[제안]**, 톤 확인용, 확정 아님):
- 첫 만남: 「또 하나 걸어 들어왔네. 신발이나 닦아.」
- 길을 물었을 때: 「길은 숲이 정해. 나한테 물을 일은 아니고.」

- 복선은 한 NPC가 연달아 반복하지 않는다. 한 번 보이고 지나간다(반복되면 우연으로 안 읽힌다는 컨셉 복선 메모와 같은 이유).
- 복선 대사에는 이전 만남, 이름, 과거를 암시하는 단어를 쓰지 않는다. 결말 후 다시 읽을 때만 의미가 생겨야 한다.
- 요정은 여주인공 포지션이 아니다(컨셉 4-2). 인연 수치는 다른 NPC와 같은 틀로 쌓이되 서브스토리·죽음 연결은 없다.
- 영어 현지화 때 반말의 시큰둥한 느낌을 살릴 번역 가이드가 필요하다. 현지화 키 단계에서 톤 메모를 키에 붙인다.

### D-11. 서브스토리 퀘스트 구성 (확정: 결정 34~37)
> 스포일러 주의: 반전과 연결되는 설계 메모. 게임 안 텍스트에는 쓰지 않는다.

- **결정 34: 서브스토리 1개 = 3단계 퀘스트.** 인연이 쌓여 열린 뒤, 3단계 완료가 비극의 트리거(컨셉 §6).
- **결정 35: 메카닉 배분. 첫째 = 파밍·건축, 둘째 = 지형 변형.**
- **결정 36: 비극은 마지막 퀘스트 후 다음 방문 때 부재를 발견하는 방식.** 컷신·알림 없음.
- **결정 37: 첫째의 사고 = 우연히 낡은 건물이 무너짐.** 플레이어가 지은 건축물과 무관한 원래 건물이다(우연이어야 하고 플레이어 과실로 읽히지 않게).

#### 공통 규칙 (컨셉 §6 이식)
- 열림 조건은 숨겨진 인연 수치. 컨셉 [구현]은 화제를 처음 들으면 +1, 부탁을 끝내면 +3. 열리는 임계값은 **[측정]**(미정). UI에 수치·게이지·경고를 표시하지 않는다.
- 단계 완료는 항상 보상이 있다(레시피, 재료, 지도 정보 등). 서브스토리를 진행하면 콘텐츠가 순증한다는 컨셉 규칙을 지킨다. 구체 보상은 미정.
- 비극 이후에도 해당 인물의 흔적(소지품, 건물, 기록)이 남는다. 대체 불가능한 기능은 없다(컨셉 §6).
- 되돌려 다시 해도 결말은 같다. 게임은 막지도 사과하지도 않는다.

| 3 | 건너편 조사에 동행: 지형을 파거나 쌓아 접근한다. 이 단계에서 둘째가 주인공이 원인임을 어렴풋이 눈치채는 장면 1회 | 지형 변형 |
| 비극 | "서서히 알면서도 못 막음": 단계마다 신호가 쌓인다(말투, 안색, 행동 등, 신호 종류 미정). 3단계 후 다음 방문 때 그가 없다. 설명 없음 | 환경 연출 |
- 사인(결정 42): 경계에 오래 노출된 몸이 서서히 망가진다. 원인(경계 자체의 영향인지 등)은 설명하지 않는다.
- 마소 설정 변경(결정 43~46, 부록 D-12)으로 충돌이 해소됐다. 미오의 쇠약은 짙은 마소에 오래 노출된 일반 사람이 입는 해로 설명된다. 게임 안에서는 설명하지 않고 단서만 쌓는다(결정 46).
- 눈치채는 장면의 대사는 결말 전에는 다르게 읽혀야 한다(예: 수상쩍어하는 시선이 아니라 질문을 삼키는 정도). 구체 대사 미정.
- 지형 변형을 퀘스트 해법으로 쓰는 것은 P0 프로토타입 D가 성립해야 가능하다. 불가 시 이 서브스토리의 메카닉을 건축·탐험으로 대체한다. **[제안]**

#### 제작 부담 **[제안]**
- 퀘스트 8개(결정 65: 열쇠 부탁 2 + 서브스토리 6) + 부재 발견 환경 연출 2개 + 인물 대사. 사이드 퀘스트 목표(P2-5, 20~30개)에 포함해 계산한다.
- 슬라이스에는 첫째의 1단계만 넣어 인연 수치 틀·퀘스트 파이프라인·대화 톤을 검증한다.

### D-12. 마소 설정 변경 (확정: 결정 43~46)
> 스포일러 주의: 반전과 직결되는 설계 메모. 게임 안 텍스트에 쓰지 않는다.

**결정 43: 마소가 몸에 쌓여 강해지는 것은 판타지 세계의 주민과 주인공으로 한정한다.** (주인공의 영혼이 원래 판타지 세계의 영혼이기 때문 — 컨셉 §7 반전.)
- 일반 사람(현대 생존자)은 짙은 마소에 노출되면 건강이 나빠진다. 미오의 쇠약이 이 설정으로 설명된다.
- 컨셉 §2-3의 "몸에 쌓을수록 마력을 더 강하게 쓸 수 있다"는 이 설정으로 **대체**한다. 컨셉 원문(`story-concept-2d.md`)은 사용자 원본이라 수정하지 않았다. 충돌 시 이 부록이 이긴다.

**결정 44: "겹침 이후 누구나 조금씩 마법을 쓸 수 있게 됐다"(컨셉 §3-3)는 유지한다.** 일반 사람도 옅은 마소에서는 소량 쓸 수 있고 짙은 곳에서는 해롭다. 이 문구는 주인공에게만이 아니라 일반 생존자에게도 반쪽짜리 진실이 된다(옅은 곳에서는 맞고 짙은 곳에서는 위험).

**결정 45: 일반 사람의 해는 사람마다 다르고 언제 나빠질지 모른다.**
- 규칙 시스템으로 시뮬레이션하지 않는다. NPC의 쇠약은 각본(서브스토리 단계, 환경 연출)이다. 예측 불가능성은 연출 규칙이지 수치 규칙이 아니다.
- 지역 농도(결정 21)는 일반 사람이 머물 수 있는 곳을 정하는 기준으로도 쓰인다. 시가지(옅음)에 생존자가 모여 있는 이유가 이 설정으로 자연스럽게 설명된다. 경계지·요정숲에 사람 NPC를 두면 미오처럼 위험을 안고 있다는 신호가 된다.
- 판타지 세계 주민(요정, 몬스터)은 짙은 마소에서 해를 입지 않는다.

**결정 46: 일반 사람에게 마소가 해롭다는 사실은 단서만 쌓고 설명하지 않는다.**
- 단서: 미오의 쇠약, 생존자들이 시가지를 떠나지 않는 것, 흩어진 기록의 조각.
- 플레이어 자신은 짙은 마소에서 이상이 없다. 이 차이가 복선이다(컨셉 복선 후보 4번 "마경에서 주인공만 이상 반응이 없다"를 경계지·요정숲으로 확장).
- 기록 문구에 마소의 해로움을 직접 적지 않는다.
- 위험: 단서가 너무 명확하면 반전을 일찍 추측하게 만든다. 플레이테스트에서 "플레이어가 언제 이상함을 알아챘는가"를 측정한다. **[제안]**

**영향 받는 기존 설계**
| 기존 | 영향 |
|---|---|
| 노인·낯선 사람 | 시가지(옅음)에 머무는 이유가 설정으로 설명됨 |
| 요정 NPC | 마소에 영향을 받지 않음. 사람 NPC와 구분되는 점으로 대사에 쓸 수 있으나 설명하지 않음 |

### D-13. 지역 몬스터 재설계 (확정: 결정 47~49)
> 컨셉 §2-4의 원칙을 따른다: 몬스터는 판타지 세계에서 넘어온 것들이고 악의가 없다(배고프거나 영역을 지키거나 원래 그렇다). 대부분 피할 수 있다.

- **결정 47: 시가지 몬스터는 "길 잃고 약해진 판타지 짐승 + 새끼".** 마소가 옅은 시가지로 흘러와 약해진 것이 새끼를 지킨다. 사람들이 "들개"라고 부른다(호칭일 뿐 정체는 현대의 개가 아니다). 컨셉의 행동 규칙(개 소굴을 지킴, 영역을 벗어나면 쫓지 않음)은 그대로 이식한다.
- **결정 48: 불나비·가시뿌리는 설계를 그대로 유지하고 서사 의미만 덧붙인다.**
- **결정 49: "적대적인 존재"는 던전에만 등장한다.** 1.0에서 지역 필드에는 두지 않는다.

| 지역 | 몬스터 | 마소/영역 규칙 | 서사 의미 | 연결 |
|---|---|---|---|---|
| 튜토리얼 통로 | 없음 | — | 걷기·줍기만 | |
| 무너진 시가지 | 들개(호칭) | 영역을 벗어나면 쫓지 않음. 개 소굴(짐 더미) 지킴. 마소 옅음 → 약함(난이도 낮음, 절대수칙 1) | 겹침이 비껴간 곳에 흘러온 것. 새끼를 지킴 | 낯선 사람·노인 대사에 활용 가능 |
| 경계지 | 불나비 | 잘라낸 자리 위에만 삶. 한 칸 물러서면 안 쫓음. 사람보다 느림 | 땅과 함께 떨어져 나와 그 땅에 묶인 것. **불나비가 서 있는 자리가 경계 표지** | 미오의 측량 퀘스트 단서, 기록 8번 |

**제약 / 확인 사항 [제안]**
- 판타지 짐승은 결정 43에 따라 마소의 해를 입지 않는다. 시가지에서 "약해진" 것은 마소 부족 때문이다(옅은 마소에서 약해짐). 이 설정이 일관되려면 판타지 주민·몬스터가 마소가 옅은 곳에서 약해지는 규칙이 있어야 한다. 요정이 시가지로 오지 않는 이유와도 연결 가능. 구체 규칙은 미정.
- 적대적인 존재를 던전에만 두면 필드는 "악의 없는 몬스터" 톤으로 통일된다. 던전은 회귀 실마리(기록)가 있는 곳이라 공포를 가장 약하게 쓰되 존재감을 두는 정도로 설계한다.
- 몬스터 종류 수가 3종(+던전)이라 1인 개발 분량에 맞는다. 모델·애니메이션·행동 AI는 영역 규칙(컨셉 [구현])을 재사용할 수 있다.
- "들개"라는 호칭은 한국어 단어다. 영어 현지화에서는 'strays' 계열의 호칭이 필요하다(현지화 키에 톤 메모).

### D-14. 판타지 존재의 마소 의존 규칙 (확정: 결정 50~52)
- **결정 50: 판타지 존재(몬스터·요정·주민)의 능력치는 지역 마소 농도에 비례해 연속적으로 변한다.** 시가지(옅음) < 경계지 < 요정숲(짙음) 순으로 강해진다. 상태 전환이나 임계값은 두지 않는다.
- **결정 51: 농도는 지역 고정값이다.** 플레이어가 세운 마력석 등은 플레이어의 발광과 밝힘만 담당하고 주변 농도를 바꾸지 않는다. 결정 21(농도가 변형 범위·내구를 정함)도 고정 농도를 전제로 한다.
- **결정 52: 요정은 시가지에 오지 않는다.** 이유는 설명하지 않는다. 플레이어가 마소 의존에서 스스로 해석한다.

구현 **[제안]**
- 지역 농도 맵(저해상도 격자) 한 장이 (1) 지형 변형 범위·내구, (2) 판타지 존재의 능력치 배율, (3) 일반 사람의 건강 위험 연출(각본), (4) 마력석 채집 밀도에 모두 쓰인다. 마소 관련 규칙이 하나의 값에서 나오므로 밸런스가 단순해진다.
- 능력치 배율의 하한을 둔다(시가지에서도 최소한의 위협). 상한은 지역 난이도 목표에 맞춘다. 구체 수치는 **[측정]**.
- 난이도: 절대수칙 1에 따라 시가지 몬스터는 가장 약해야 한다. 이 규칙이 그 요구를 만족한다.

**미결정 [제안]**: 플레이어 자신이 마소가 옅은 곳에서 약해지는가. 플레이어의 마소는 몸에 쌓은 양(보유량) 기반이므로 지역 농도에는 영향받지 않는 것으로 두는 것이 단순하다. 확정은 아니다.

### D-15. 던전의 적대적인 존재 (확정: 결정 53~56)
> 스포일러 주의: 반전과 연결되는 설계 메모. 게임 안 텍스트에 쓰지 않는다.

- **결정 53: 형태는 형체가 불분명한 그림자·윤곽형.** 저폴리에서 제작이 쉽고 정체를 설명하지 않는다는 원칙(절대수칙 4)에 맞는다.
- **결정 54: 일반 몹처럼 데미지를 주고받으며 처치할 수 있다.** 플레이어 체력이 0이 되면 던전 밖(입구)으로 되돌려진다. 컨셉의 일반 죽음 규칙(가장 가까운 회복 장소에서 깨어남)은 적용하지 않는다.
- **결정 55: 던전에서 되돌려질 때 재료 손실은 없다.**
- **결정 56: 던전 몬스터는 4종 — 적대적인 존재 3종 + 대형 1종.** 종류 수에 대한 조사 근거는 없어 선택지로 정했다.

설계 **[제안]**
| 종류 | 역할 | 비고 |
|---|---|---|
| 적대적인 존재 A | 던전 입구부 기본형 | 가장 약함. 플레이어를 골라서 따라오는 행동 규칙을 먼저 보여준다 |
| 적대적인 존재 B | 중간부, A의 변형(크기·속도·공격 방식 변주) | 같은 윤곽 모델의 색·크기 변형으로 제작량 절약 |
| 적대적인 존재 C | 심부, 다른 공격 패턴 | 지형·벽을 이용한 위치 변화 등 던전 구조와 연결 |
| 대형 | 던전 마지막(회귀 기록 앞)의 문지기 | 필수 전투 여부는 절대수칙 2/1에 따라 선택. 회피 경로를 두거나 낮은 난이도 옵션 제공 |

규칙 **[제안]**
- 필드 몬스터(영역을 벗어나면 쫓지 않음)와 달리, 적대적인 존재는 **플레이어를 골라서 따라오는 것이 특징**이다. 영역 한계 규칙은 던전 안에서만 적용(던전 밖으로 나가면 쫓지 않음).
- 쓰러뜨릴 수 있게 한 결정(54)으로 공포보다 압박이 핵심이 된다. 컨셉 톤("무섭기보다 쓸쓸하다")을 유지하려면 연출을 어둡게 하되 점프 스케어는 쓰지 않는다.
- 던전에서 되돌려져도 던전 진행 상태(열린 문, 가져온 기록)는 유지한다. 처음부터 다시 해야 하는 상황은 절대수칙 1·3과 충돌한다.
- 대형이 필수 전투이면 낮은 난이도 옵션에서 체력·공격력을 낮출 수 있어야 한다.
- 던전 구성 규칙은 마소 농도 규칙(결정 50)에 따른다: 적대적인 존재의 능력치 배율은 던전의 농도 값에 연동한다(결정 68, D-20).
- 제작량: 시가지 1종 + 경계지 1종 + 요정숲 1종 + 던전 4종 = 총 몬스터 7종. 1인 개발 분량에서는 가장 큰 단일 몬스터 풀이므로 P1 슬라이스에서 몬스터 1종당 제작 인일을 실측해 확정한다.

### D-16. 미오의 목표 (확정: 결정 57~59)
> 스포일러 주의: 반전과 연결되는 설계 메모. 게임 안 텍스트에 쓰지 않는다.

- **결정 57: 미오의 목표는 경계 너머로 가는 길을 지도에 남기는 것.** 기록 4번(「되돌리는 법을 아는 이들이 있었다고 했다」)의 단서를 추적하는 목적이 있다. 이로써 미오의 서브스토리가 회귀 실마리 3갈래(던전 기록, 판타지 주민, 흩어진 기록) 중 흩어진 기록 쪽과 이어진다.
- **결정 58: 동기는 직업의 습관 — 측량하지 않으면 불안하다.** 개인사는 드러내지 않는다. 시간이 지날수록 직업이 그의 이름이 된다.
- **결정 59: 미오가 사라진 뒤 미완성 지도는 플레이어가 이어받는다.** 미오가 남긴 지도가 플레이어 지도에 경계지 일부를 해금한다(탐험 보상). 이미 설계한 지도 시스템(마커 최소)과 자연스럽게 이어진다.

설계 **[제안]**
- 아이러니: 미오가 되돌리는 법에 가까워질수록, 되돌리는 법의 원인이 주인공이라는 사실에 가까워진다. 3단계에서 미오가 어렴풋이 눈치채는 장면(D-11)이 이 목표에서 나온다. 노골적이지 않게 질문을 삼키는 정도로 쓴다.
- 지도 보상은 3단계 완료 직후가 아니라 비극 이후(부재 발견)에 받는다. 미오의 거처나 마지막 작업 장소에 놓인 미완성 지도를 집으면 지도가 해금된다. 경고나 알림 없이, 설명 없이.
- 기존 퀘스트 구성과의 정합: 1단계 표지 확인(경계선 표지 수집), 2단계 끊긴 길에 지형 쌓기(건너편 관측 지점까지), 3단계 건너편 조사 동행. 이 3단계가 곧 "경계 너머로 가는 길을 지도에 그리는" 과정이다. 3단계 끝에서 길의 일부가 지도에 남는다.
- 지도에 그려지는 길이 실제 월드의 지형 변형 결과(플레이어가 쌓은 길)와 연동되는지는 미정. 연동되면 멋있지만 지도 시스템 구현 부담이 커진다. **[미결정]**
- 목표가 완성되는가: 완성되지 않는다. 미오는 경계 건너편에 닿지 못하고 사라진다. 게임은 건너편에 무엇이 있는지 답하지 않는다(컨셉 §9 빈칸 원칙과 같은 방향이나, 건너편 정체가 반전과 연결되는지는 별도 검토).

### D-17. 미오의 쇠약 신호 연출 (확정: 결정 60~61)
- **결정 60: 신호 채널은 대사 하나뿐.** 대사가 점점 짧아지고 같은 말을 반복한다. 지도의 선 흔들림, 행동 애니메이션(쉬는 횟수, 앉아서 측량), 외형(안색·자세) 변화는 1.0에서 쓰지 않는다. 제작량을 최소로 하고 저폴리 표현 한계를 피한다.
- **결정 61: 강도 곡선은 "거의 없음 → 눈에 띔 → 분명함".** 1단계에서는 플레이어가 의식하지 못하고, 2단계에서 "어?" 하고, 3단계에서 확인한다. 알림·경고 없음.

설계 **[제안]**
- 미오의 말투 결: 측량사답게 **숫자와 방향을 정확히 되뇌는 습관**을 가진 말투. 요정(시큰둥, 돌려 말함), 낯선 사람(짧게 끊김), 노인(길고 담담)과 구분되고, 쇠약은 이 정확한 습관이 헐거워지는 것으로 나타난다.
- 초안 대사 (톤 확인용, 확정 아님):
  - 1단계: 「북서로 사십이 보. 표지가 둘, 여기가 첫째.」
  - 2단계: 「북서로 사십이. …사십이 보. 표지가 둘.」
  - 3단계: 「사십이. 사십이. …다음 표지가 어디였지.」
- 길이는 단계마다 짧아지고, 3단계에서는 방금 한 말을 되풀이하며 숫자를 놓친다.
- 반복 대사는 같은 대화 항목을 단계에 따라 다른 변형으로 교체하는 방식으로 만들 수 있어 제작량이 적다. 대사 키마다 단계 번호를 붙인다.
- 1단계 대사에는 의도적인 흠이 없어야 한다(플레이어가 알아채지 못하는 것이 목적).
- 3단계 후 부재 발견 장면에서는 대사가 없다. 마지막 대사는 3단계 안에서 끝난다.
- 영어 현지화 때 숫자를 되뇌는 리듬을 살릴 번역 가이드가 필요하다(대사 키에 톤 메모).
- 한계: 대사 채널 하나뿐이면 일부 플레이어가 신호를 놓칠 수 있다. 플레이테스트에서 "미오가 아프다는 걸 언제 알았는가"를 측정한다. 너무 놓친다면 지도 필체 흔들림(결정 59 연동)을 추가 후보로 둔다. **[제안]**

### D-18. 서브스토리 보상과 인연 임계값 (확정: 결정 62~64)
- **결정 62: 에닐 보상 = 회복 장소 추가 + 간호 레시피.** 단계별로: 1단계 붕대 강화 레시피, 2단계 체육관을 회복 장소로 등록(체력이 차는 새 지점), 3단계 에닐의 가방(의료 재료와 상위 붕대 레시피). 비극 이후에도 체육관은 회복 장소로 남아 에닐의 흔적이 계속 쓰인다.
- **결정 63: 미오 보상 = 표지 위치 → 지형 변형 강화 → 미완성 지도 해금.** 1단계 경계 표지 위치가 지도에 표시, 2단계 지형 변형 범위의 소폭 확장(길 쌓기 체험의 보상), 3단계 비극 이후 미완성 지도로 경계지 일부 해금(결정 59).
- **결정 64: 서브스토리가 열리는 인연 임계값은 5 — 첫 부탁(+3) + 화제 2개(+1씩).** 컨셉 [구현]의 +1/+3 값 기준이다. 수치·게이지는 플레이어에게 보이지 않는다.

정합성 / 확인 사항 **[제안]**
- **"첫 부탁"의 정의를 분명히 한다.** 임계값 5의 첫 부탁(+3)은 서브스토리 *이전*에 받는 열쇠 부탁(컨셉 낯선 사람의 천 조각 3개 → 고철 4 + 전선 2 같은 것)이다. D-11의 1단계는 서브스토리가 열린 *뒤*의 첫 퀘스트다. 열쇠 부탁을 별도 퀘스트로 둘지, 1단계를 열쇠로 겸할지 확정이 필요하다. 기본안은 **별도(열쇠 부탁 1개 + 서브스토리 3단계 = 인물당 퀘스트 4개)**이다. 이 경우 두 인물 합계 퀘스트는 8개가 된다(D-11의 6개에서 증가).
- 화제 수(인물당 4개)는 컨셉 노인·낯선 사람의 구조를 따른 **가정**이다. 에닐·미오의 대사 설계 시 확정한다.
- 임계값 5는 보통 한두 번 방문하고 첫 부탁을 끝내면 열리는 값이다. 서브스토리를 피하는 플레이도 유효하다(첫 부탁과 화제를 건너뛰면 열리지 않는다). 컨셉 §6의 "경고 없음, 피하는 플레이는 유효하지만 유리하지 않음"에 맞다.
- 보상 균형: 에닐 보상(회복 장소)은 생존 편의, 미오 보상(변형 범위 확장)은 핵심 시스템 강화다. 미오 쪽 보상이 더 강하다. 지형 변형 범위 확장은 밸런스에 영향을 주므로 P0 프로토타입 D에서 기본 범위와 확장 폭을 같이 측정한다. 서브스토리를 피한 플레이어가 지형 변형을 못 쓰게 되지는 않아야 한다(기본 범위로도 모든 필수 진행이 가능하도록). **[제안]**
- 비극을 겪게 하는 대가로 얻는 보상이므로 보상 수령 연출은 최소화한다(보상 텍스트에 축하하는 톤 금지).

### D-19. 열쇠 부탁 (확정: 결정 65)
- **결정 65: 열쇠 부탁은 서브스토리 1단계와 별도 퀘스트로 둔다.** 인물당 퀘스트 4개(열쇠 부탁 1 + 서브스토리 3단계), 두 인물 합계 8개. 결정 64(임계값 5 = 열쇠 부탁 +3 + 화제 2개)는 그대로 유효하다.
- 열쇠 부탁은 컨셉의 낯선 사람 첫 부탁(천 조각 3개를 건네면 고철 4 + 전선 2를 받음, 수락/거절 창 없음 — 묻는 것이 곧 받는 것) 방식을 따라, 평범하고 보상이 즉각적인 작은 부탁으로 만든다. 서브스토리의 시작이 뒤통수가 되도록 사전 경고를 주지 않는다.
- 제작량: D-11의 "퀘스트 6개"는 8개로 갱신한다. 사이드 퀘스트 목표(P2-5)에 포함해 계산한다.
- **결정 66: 에닐의 열쇠 부탁 = 약통으로 쓸 플라스틱을 모아 달라는 부탁.** 플라스틱 2개 전달 → 보상은 천 조각 소량(**[제안]**, 구체 수량 미정).
- **결정 67: 미오의 열쇠 부탁 = 측량 막대를 만들 고철과 전선을 모아 달라는 부탁.** 고철 2 + 전선 2 전달 → 보상은 판자 소량 등 **[제안]**(구체 수량·품목 미정).
- 위 구체 수량(2개씩)은 제 초안값이다. 확정이 아니며 제작 단가와 파밍 밀도에 맞춰 조정한다. **[측정]**
- 주의 **[제안]**: 에닐 열쇠 부탁의 보상이 천 조각이면 1단계(천 조각 전달)와 재료가 이어진다. 의도적으로 1단계 재료를 미리 쥐여 주는 효과가 되지만, 플레이어가 "같은 재료를 반복한다"고 느낄 수 있어 보상을 다른 재료로 바꿀 수 있다.
- 두 부탁 모두 컨셉의 낯선 사람 첫 부탁 방식(수락창 없음, 묻는 것이 곧 받는 것)을 따른다. 서브스토리로 이어진다는 경고는 주지 않는다.
- 이 부탁의 목적은 인물의 성격을 한 번 보여 주는 것: 에닐은 약통(돌봄), 미오는 측량 막대(정확함). 대사에서 미오는 수량을 정확히 요구하는 말투를 쓴다(D-17의 말투 결과 연결).

### D-20. 던전 규칙 결정 (확정: 결정 68~70)
- **결정 68: 던전의 적대적인 존재 능력치는 마소 농도와 연동한다.** 던전의 농도 값을 쓴다(결정 50의 농도 맵에 던전 구역 값 포함).
- **결정 69: 던전 마지막 대형 적을 쓰러뜨리는 것은 진행에 필수이되, 지형 변형으로 쓰러뜨릴 수도 있다.** 공략법이 하나가 아니게 한다(곱셈형 설계).
- **결정 70: 플레이어는 마소가 옅은 곳에서 약해지지 않는다.** 플레이어의 마소는 몸에 쌓은 양 기준이며 지역 농도에는 영향받지 않는다(D-14의 미결정 항목 해소).

정합성 / 확인 사항 **[제안]**
- **던전 농도 값 미정.** 던전은 시가지에 입구가 있지만 안은 겹침이 남긴 구멍이다. 기본안은 경계지 수준의 중간 농도로 시작하고, 난이도 목표(절대수칙 1)에 맞춰 조정한다. **[측정]**
- **절대수칙 1 방어 필요**: 농도에 연동되면 짙을수록 적이 강해진다. 능력치 배율에 상한을 두고, 대형이 필수 전투이므로 **낮은 난이도 옵션이 필수 기능**이 된다. 낮은 난이도에서는 체력·공격력 배율을 낮추거나 지형 변형 공략의 효과를 키운다.
- **절대수칙 2와의 관계**: 대형 필수 전투는 메인 진행의 조건이지 월드 전체를 잠그지 않는다. 앞서 "이동기/도구 해금 허용"으로 수칙 2를 "메인 스토리 이탈 자유"로 해석한 것과 일치한다. 던전을 잠그는 시점(회귀 실마리 첫째 갈래)은 여전히 미정이다.
- **지형 변형 공략 설계**: 대형 적과 지형 변형의 상호작용(함정 파기, 발판 쌓기 등)이 가능한 전투 공간이어야 한다. 던전이 지하 공간이므로 변형 가능한 지면 영역을 대형 전투방에 확보해야 한다. 변형 불가 영역(결정 21의 마소 농도에 의한 내구)과 충돌하지 않게 한다. P0 프로토타입 D에서 전투방 샘플을 같이 검증한다.
- **제작 부담**: 대형이 필수 전투이면서 지형 변형으로 공략 가능해야 하므로 던전에서 가장 비싼 단일 콘텐츠가 된다. P1 슬라이스에서는 던전 전체가 아니라 대형 전투방 하나로 미니 던전을 만들어 지형 변형 공략을 검증하는 안을 제안한다.
- 필수 전투이므로 낮은 난이도에서도 막히는 플레이어를 위해 충분한 힌트(환경 단서)를 둔다. 설명하지 않는다는 원칙(절대수칙 4)은 지키되, 지형 변형이 해법이라는 신호는 환경으로 준다.

### D-21. 지도와 지형 변형 (확정: 결정 71)
- **결정 71: 지도는 원본 지형 기준이며 플레이어의 지형 변형 결과를 반영하지 않는다.** 변형 결과는 월드에서만 보인다.
- 미오의 이어받은 지도(결정 59)는 원본 경계지의 윤곽과 길 표시를 해금하는 방식이다. 미오의 서브스토리 2단계에서 플레이어가 실제로 쌓은 길과 지도의 길 표시는 연동되지 않는다. D-16의 미결정이 이로써 해소된다.
- 이유 **[제안]**: 1인 개발·저사양 목표에서 변형 델타를 지도 렌더링에 연결하는 작업과 갱신 비용을 아낀다. 지도는 이미 마커 최소·안개 기반이라 원본 기준이어도 탐험 기록 기능은 유지된다.
- 아쉬움: 플레이어가 쌓은 길이 지도에 남지 않는다. 변형 결과를 기억할 방법은 월드 안 단서(건축물, 쌓인 지형)뿐이다. 플레이테스트에서 "내가 만든 길을 찾기 어렵다"는 불만이 많으면 "일부 반영"으로 올리는 후보를 둔다. **[제안]**
- 세이브: 변형 델타는 세이브에 저장하되(P0 프로토타입 D), 지도 데이터와는 분리한다.

### D-22. 남은 미결정 항목 결정 기록 (GDD 1.0 이후)
- **결정 72: 던전의 마소 농도는 깊어질수록 짙어진다.** 입구는 시가지 수준(옅음), 심부는 요정숲 수준(짙음). 구간별 값은 **[측정]**. 농도 맵이 지역이 아니라 던전 안에서 기울기를 가져야 하므로, 농도 맵은 던전 내부 구역별 값을 지원해야 한다. 대형 전투방이 가장 짙은 곳이라 지형 변형이 가장 강하게 들고(범위·내구) 적도 가장 강하다.

- **결정 73: 던전 대형 전투의 지형 변형 공략법은 두 가지 방식을 번갈아 쓰고, 던전마다 다르게 설계한다.** 두 방식: ① 함정·함몰(대형의 이동 경로에 구덩이를 파서 빠뜨림) ② 발판·장벽(쌓아서 높이를 확보해 약점을 노리거나 장벽으로 공격을 막음). 이 원칙은 후속 던전(출시 후 드워프 마을 등)에도 적용한다.
- **결정 74: 1.0의 던전 1개 대형은 함정·함몰을 주된 공략법으로 한다.** 발판·장벽은 후속 던전의 차별화 요소로 아껴 둔다. 구현 필요: 대형의 이동 경로 AI와 지형 변형의 충돌 처리(구덩이에 빠졌을 때의 상태, 탈출 시간), 대형 전투방에 변형 가능한 지면 확보(변형 불가 영역 규칙과 충돌 금지). 낮은 난이도에서 더 쉬운 공략이어야 하므로 구덩이에 빠진 대형의 무방비 시간을 길게 한다. **[제안]**

- **결정 75: 에닐·미오의 화제는 인물당 4개.** 처음 들으면 +1씩(최대 4). 임계값 5(결정 64)는 열쇠 부탁(+3) + 화제 2개로 도달하며, 화제 4개를 모두 들으면 +4, 열쇠 부탁까지 하면 최대 7이다.
- **결정 76: 열쇠 부탁 수량은 에닐 플라스틱 2 / 미오 고철 2 + 전선 2.** 채집 밀도 실측 후 조정할 수 있다. **[측정]**

- **결정 77: 에닐 열쇠 부탁 보상 = 유리 조각 + 고철 약간.** 1단계(천 조각 전달) 재료와 겹치지 않는다. 구체 수량은 **[측정]**.
- **결정 78: 미오 열쇠 부탁 보상 = 판자 소량 + 플라스틱 1.** 미오가 정확한 수량을 요구하는 말투에 맞춰 보상도 정확한 수량으로 준다. 판자 수량은 **[측정]**.

- **결정 79: 월드 크기는 "중간" — 지역 간 이동에 수 분, 넓은 탐험 공간.** 숫자(km², 지역별 치수)는 근거가 없어 정하지 않고 P1 측정치로 확정한다.
  - **긴장 관계 [경고]**: 이는 설계 기둥 2(밀도 > 크기), 1인·파트타임·외주 없음 전제와 부딪친다. 중간 크기는 지형 제작량, 스트리밍 부담, 지형 변형 저장 크기, 빈 구간 위험을 모두 키운다. 일정 단축 방안(결정 27)의 첫 후보가 "월드 크기 축소"가 된다.
  - 완화책 **[제안]**: ① 크기를 늘리는 대신 수직성(산이 직선 이동을 막음, R 4.1)과 삼각형 규칙으로 체감 크기를 만든다. ② 4지역이 서로 이웃하게 배치해 지역 간 이동을 짧게 유지한다. ③ 빈 구간을 막기 위해 POI 클러스터를 먼저 배치하고 사이를 채운다. ④ P0 엔진 게이트의 테스트 월드(8~16km² 가정)로 상한을 확인한 뒤, P1 측정으로 실제 km²를 정한다.

- **결정 80: 메인 스토리는 실마리 수집형.** 회귀 실마리 조각을 일정량 모으면 마지막 에피소드가 열린다. 조각을 모으는 순서는 자유다. 별도의 선형 메인 퀘스트 줄(8~12 구간)은 만들지 않으며 P2-5의 "메인 1줄(8~12 구간)" 가정은 이 결정으로 대체한다(제작량 감소).
- **결정 81: 던전은 이동기/도구 해금 후에 열린다**(예: 지형 변형 강화 또는 특정 도구). 절대수칙 2(진행 잠금 없음)를 "메인 스토리 이탈 자유"로 해석한 결정 15의 범위 안이다. 해금 도구는 월드 탐험의 보상으로 얻는다.
- 정합성 확인 필요 **[제안]**:
  - 해금 도구가 미오 서브스토리의 보상(지형 변형 범위 확장)이면, 서브스토리를 피한 플레이어는 던전에 못 들어간다. 서브스토리를 피하는 플레이는 유효해야 하므로(결정 64의 취지) **해금 도구는 서브스토리와 무관하게 얻을 수 있어야 한다.**
  - 마지막 에피소드를 여는 "일정량"이 던전 기록(첫째 갈래)을 반드시 포함하는지, 던전 없이도 채울 수 있는지 정해야 한다. 던전의 대형이 진행 필수(결정 69)인 점과 이어진다.

- **결정 82: 던전을 여는 해금 도구는 서브스토리와 무관한 별도 도구를 월드 탐험으로 얻는다.** 미오·에닐 서브스토리를 피한 플레이어도 던전에 갈 수 있다. 도구 이름·형태·획득 장소(경계지 또는 요정숲 POI 후보)는 **[미결정]**이고 추가로 설계해야 한다. 지형 변형 강화와는 별개다.
- **결정 83: 마지막 에피소드를 여는 실마리 "일정량"에 던전 기록(첫째 갈래)을 반드시 포함한다.** 던전 대형 전투(결정 69)가 진행에 필수이고, 던전을 안 가면 결말에 못 가며, 회귀 실마리 3갈래가 모두 의미를 갖는다. 나머지 두 갈래(요정, 흩어진 기록)는 수집량을 채우는 자유 조각이다. 일정량의 정확한 개수와 갈래별 조각 수는 **[측정]**.
- 위 결정 81의 정합성 확인 항목 두 개가 이로써 해소됐다.

### D-23. 던전 해금 도구 설계 (확정: 결정 84~86)
- **결정 84: 던전 입구는 낙반(무너진 잔해)으로 막혀 있다.** 시가지(겹침이 비껴간 무너진 도시)의 분위기와 맞고 마소·물 규칙에 의존하지 않는다.
- **결정 85: 해금 요소는 설계도(레시피)를 얻어 직접 만드는 도구.** 낙반을 치우는 도구(굴착·철거용, 이름 가칭 "굴착 도구")를 제작한다. 파밍 → 제작 루프와 일치하고, 재료 요구량으로 해금 시점을 조절할 수 있다. 완성된 도구를 바로 얻는 방식은 쓰지 않는다.
- **결정 86: 설계도는 경계지의 POI에서 얻는다.** 미오 서브스토리(경계 표지)와 지역은 겹치지만 퀘스트와는 무관하다.

설계 메모 **[제안]**
- **도구 정체**: 컨셉의 쇠지렛대(자판기 개봉·채집 보너스)의 상위 도구로 읽히게 한다. 건축물 부수기(조리법 절반 환급)보다 한 단계 큰 잔해를 치우는 도구. 이름·재료 구성은 미정이며 기본 재료 6종(+ 마력석 여부)으로 구성하고 요구량은 **[측정]**.
- **획득 POI**: 경계지의 양쪽 세계 경계 근처, 현대 쪽 공사 장비/현장 잔해에서 설계도를 발견하는 형태. 불나비가 지키는 자리 인근에 둘 수 있다. 설명 없이 월드에 놓아 둔다. 구체 위치는 월드 배치 때 결정.
- **재사용 가치**: 같은 도구가 시가지 곳곳의 낙반으로 막힌 샛길·지름길·건물 입구에서도 쓰이면 해금 도구가 던전 문 하나로 끝나지 않고 탐험 보상이 된다. 낙반 제거 가능 지점의 수는 P1 측정 후 정한다.
- **동선**: 시가지에서 시작하는 플레이어는 경계지(마소 중간~짙음, 몬스터는 불나비)를 한 번 탐험해야 던전에 갈 수 있다. 시가지가 시작 지역이고 던전 입구도 시가지에 있으므로 "되돌아오는 동선"이 생긴다. 지도·랜드마크로 던전 입구 위치를 환경으로 알려 준다.
- **절대수칙 정합**: 진행 잠금(수칙 2)은 "메인 스토리 이탈 자유" 범위의 해금이다. 설계도는 서브스토리와 무관하게 얻을 수 있으므로 서브스토리를 피한 플레이어도 던전에 갈 수 있다. 수칙 1(어렵지 않게): 설계도 획득 POI는 불나비 한 마리 수준의 약한 위협으로 유지.
- 낙반 제거 연출은 단순하게(잔해 모델 제거 + 길 열림). 별도 컷신 없음.

### D-24. 실마리 조각 개수 (확정: 결정 87~88)
- **결정 87: 실마리 조각은 총 14개 — 흩어진 기록 8 + 요정 대사 4 + 던전 기록 2.** 던전 기록 2개 중 1개는 필수 조각(던전 마지막), 1개는 던전 안의 선택 조각이다.
- **결정 88: 마지막 에피소드를 여는 일정량은 약 60% — 14개 중 8개.** 필수 던전 조각 1개 + 나머지 7개는 자유.

정합성 확인 **[제안]**
- 8개를 채우는 최단 경로: 던전 필수 조각 1 + 흩어진 기록(시가지·경계지) 7 = 8. 요정숲을 가지 않아도 마지막 에피소드가 열린다. 그러면 요정의 "주인공을 알아보는 듯한 반응" 복선(결정 33)과 요정숲 경험을 건너뛰는 플레이가 가능하다. 이는 절대수칙 2(진행 잠금 없음)에 맞는 설계지만, 요정 쪽을 안 본 플레이어에게 복선이 전달되지 않는다. 복선 전달 경로가 요정 하나에만 의존하지 않도록 다른 복선 후보(주인공만 이상 없음, 마법 습득이 빠름)를 병행해 둔다.
- 흩어진 기록 8장은 시가지(짝수 번)·경계지(홀수 번)에 있어 4지역 중 요정숲이 조각 수집의 필수 지역이 아니다. 요정 조각 4개는 요정숲에서만 얻는다.
- 단서가 없는 플레이: 8개 중 가장 적은 정보 조합은 던전 필수 1 + 흩어진 기록 7이다. 기록 1·3·5·6(서사 조각)이 전부 답을 주지 않으므로 최소 조합에서도 결말 분기 선택의 맥락이 되는지 플레이테스트로 확인한다. **[측정]**
- 각 조각은 한 줄로 주어지지 않고 세계 곳곳에 흩어져 있어야 한다(결정 80). 조각 수집 상태를 UI에 표시하지 않는다(진행 게이지 없음, 절대수칙 4).
- 마지막 에피소드가 열린다는 사실을 플레이어가 알게 하는 신호(장소·NPC·연출)는 미정.

- **결정 89: 마지막 에피소드가 열렸다는 신호는 "회복 장소에서 쉴 때 짧은 장면 + 월드 한 곳이 변한다."** 수치·게이지·알림은 없다.
- **결정 90: 마지막 에피소드는 시가지의 랜드마크(녹슨 철골)에서 시작한다.** 시작 지역으로 돌아온다.

설계 메모 **[제안]**
- **트리거**: 실마리 조각이 8개가 된 뒤 *처음으로* 회복 장소에서 쉬면 짧은 장면이 한 번 나온다. 모든 지역에 회복 장소가 있고 시가지 랜드마크도 회복 장소이므로 어떤 플레이 경로에서도 작동한다.
- **장면 내용**: 짧은 꿈. 주인공의 기억의 구멍(복선 후보 5번)과 이어지게 하되 반전을 직접 말하지 않는다. 내용·길이는 미정. 설명이나 자막 안내 없이 끝난다.
- **월드의 변화**: 어느 곳이 변하는지는 미정이지만, 마지막 에피소드가 시작되는 시가지 랜드마크(녹슨 철골) 자체가 변하는 안을 기본으로 한다. 변화는 눈에 띄게 하되 설명하지 않는다(예: 빛, 색, 소리). 구체 연출은 아트 단계에서 결정.
- **자유 유지**: 열렸다고 해서 강제로 진행되지 않는다. 플레이어는 마지막 에피소드를 열지 않은 채 탐험·건축·서브스토리를 계속할 수 있다(수칙 2). 에피소드를 시작하는 방법은 랜드마크에 가서 하는 행동이다(구체 상호작용 미정).
- **원점 회귀**: 시작 지역에서 끝난다. 쓸쓸한 톤과 수미상관. 첫 회복 장소에서 마지막 선택(§10 결말)이 이루어진다.
- 신호를 놓칠 수 있는 플레이어(회복 장소에서 쉬지 않는 플레이)는 없다: 체력이 회복 장소에서만 차기 때문이다(컨셉 규칙). 단, 회복 장소를 안 쓰고 지내는 극단적 플레이는 테스트로 확인한다. **[측정]**

- **결정 91: 개발 중 생활비는 본업/현재 수입을 유지하며 병행한다.** 추가 생활비 부담이 없다.
- **결정 92: 개발용 PC·장비는 현재 장비로 충분하다.**
- **결정 93: 개발 도구·에셋·음악 소프트웨어 등의 월 예산은 5만 원 이하**(금액 단위는 원으로 가정). 개발 기간 환산 60~102개월이면 총 약 300~510만 원 상한이다. 총 가용 금액의 확정 값은 이 상한과 출시 시점 비용(스팀 등록비, 심의비)의 합으로 본다. **[가정]**

### D-27. 결정 11의 범위 정리 (확정: 결정 94)
- **결정 94: 기본은 무료·오픈소스 도구로 작업한다.** 결과물이 마음에 들지 않을 때 유료 도구(에셋·플러그인)를 쓸지는 **그때그때 사용자가 결정한다.** 결정 11("외주·에셋 구매 없음")은 이 범위로 해석한다: 외주는 계속 배제, 에셋·도구 구매는 기본 금지이되 사용자 판단으로 예외 허용.
- 영향: 엔진 게이트에서 유료 에셋은 처음부터 시험하지 않는다(무료 후보 먼저). 무료 후보가 불합격이면 유료 후보를 시험하기 전에 **사용자에게 구매 여부를 묻는다.** 구매 한도는 결정 93(월 5만 원 이하)을 따른다.

- **결정 95: 저사양 테스트용 기기는 구하지 않고 현재 장비에서 근사 측정만 한다.** 근사했다는 사실을 모든 측정 결과에 기록한다. 출시 전 베타에서 실제 저사양 기기 사용자 피드백으로 보완한다. 현재 장비의 정확한 사양은 **사용자가 알려 주기로 함**(제가 사용자의 PC에 접근할 수 없음; 연결 가능한 폴더도 없었음).

- **결정 96: 현재 PC 사양 기록 및 근사 측정 규칙.** 사용자가 CPU-Z 스크린샷으로 제공: i5-12400F(6C/12T), DDR4 32GB 듀얼 채널, RTX 3060 Ti 8GB, B660M DS3H DDR4. 저장장치·OS는 미확인. 이 PC는 목표 최저 사양보다 훨씬 강하고 내장 그래픽이 없어 통합 그래픽을 직접 재현할 수 없다. 근사 측정은 720p·최저 품질, CPU/GPU 프레임 비용 분리 기록, 메모리 8GB 제한 시험(가능 여부 미확인), 평균 프레임타임이 합격선의 50% 이하일 때 합격이라는 안전 마진(**[가정]**) 규칙을 쓴다. 상세는 `engine-gate-plan.md` §3.1.

- **결정 97: 합격선은 현재 가정값 그대로 시작하고, 첫 측정 후 필요할 때만 조정한다.** 대상: `engine-gate-plan.md` §4~§5와 `prototype-d-spec.md` §6의 모든 수치(평균 33ms·99퍼센타일 50ms·입력 지연 100ms·히치 0회·저장 1초/불러오기 3초 등)와 안전 마진 50%. 조정은 측정 결과에 근거할 때만 하며, 조정 이력은 각 문서 하단에 남긴다. 근거 없는 숫자를 반복해서 바꾸지 않는다.

- **결정 98: 결정 21의 "내구"는 최대 한계로 정의한다.** 쌓을 수 있는 최대 높이·깎을 수 있는 최대 깊이가 마소 농도에 따라 다르다. 시간 경과로 지형이 되돌아가는 침식 방식은 쓰지 않는다. 저장이 단순하고 되돌려도 결과가 같으며(수칙 3) 건축물·서브스토리 길이 사라지지 않는다. "오래간다"는 느낌은 한계의 차이로 표현한다. `prototype-d-spec.md` §5.2.1의 기본안 ㄱ을 확정한다.

- **결정 99: 건축물 규칙은 "기초 보호"로 한다.** 플레이어가 지은 건축물의 바닥 면과 여유 1칸은 지형 변형이 불가능하며 변형 불가 영역을 표시한다. 건축물이 허공에 뜨거나 부서지는 일이 없다. 이는 에닐 대피소(판자 바닥·벽·문 설치)와 같은 건축 서브스토리의 결과물이 변형으로 망가지지 않게도 한다. 표시 방식(UI·월드 표식)은 P1 UX에서 정한다. 프로토타입 D §5.4 ㉠을 확정한다. ㉡·㉢은 ㉠이 불합격일 때만 시험한다.

- **결정 100: 엔진 게이트는 엔진당 2주 상한을 유지한다**(파트타임 기준). 초과하면 그 시점의 측정으로 판정한다.
- **결정 101: 가산 항목 가중치는 그대로 쓴다**(지형 변형 재미 3, 구현 시간 3, 던전 대응 2, 메모리·디스크 2, 학습 곡선 2, 데이터 중심 1, 배포 1). 측정 후 필요할 때만 조정한다.

- **결정 102: 현재 PC의 저장장치는 SSD(NVMe 또는 SATA, 정확한 종류 미확인), 운영체제는 Windows.** 저장·불러오기 합격선(저장 1초, 불러오기 3초)은 SSD 기준이다. 저사양 사용자는 HDD일 수 있으므로 불러오기 시간은 HDD 환경에서 더 길어질 수 있음을 기록하고, 출시 전 베타에서 보완한다.

- **결정 103: 회복 장소에서 쉴 때 나오는 짧은 장면(꿈)은 이름 없는 풀밭과 소품 하나만 보여준다.** 대사·인물·설명 없이 장면 한 컷. 어떤 소품인지(예: 낡은 물건)는 아트 단계에서 정한다. 질문의 선택지 이름이 오타로 흐려져 소품의 정확한 종류는 확정하지 않았다.
- **결정 104: 마지막 에피소드는 랜드마크(녹슨 철골)의 회복 장소에서 쉴 때 나타나는 추가 선택지로 시작한다.** 평소 쉬는 행동에 선택지가 하나 더 붙는다. 알림·UI 마커 없이 마련되며, 실수로 시작하지 않도록 확인 단계를 둔다. 실마리 조각이 일정량 모이기 전에는 이 선택지가 나타나지 않는다.

### D-28a. 해금 도구 "폭파장치"와 마력석 설정 (확정: 결정 105~107)
- **결정 105: 낙반을 치우는 해금 도구의 이름은 "폭파장치"다**(사용자 제안, 가칭 "굴착 도구" 대체). 설계도는 경계지 POI에서 얻는다(결정 86).
- **결정 106: 새 세계 설정 — 겹침 이후 현대 재료만으로는 전기·기계 장비를 온전히 쓸 수 없고, 마력석이 그 장비의 기초 재료로 필요하다.** 적용 범위는 **전기·기계 장비류**(폭파장치, 마력석 등, 활용 장비)만이다. 건축(판자 바닥·벽·문), 쇠파이프·쇠지렛대 같은 단순 도구, 붕대 같은 소모품은 현대 재료만으로 만든다.
- **결정 107: 시가지에는 마력석이 거의 없고 경계지에서 얻는다**(컨셉 유지). 마력석이 필요한 장비는 경계지 탐험 후에 만들 수 있다. 시작 지역의 기본 제작·건축 루프는 현대 재료만으로 돌아간다.

설계 메모 **[제안]**
- **설정의 일관성:** 컨셉 §2-3 "겹침으로 마소가 현대세계의 모든 것에 영향을 준다"에 부합한다. 전기·기계 장비가 마소 없이는 작동하지 않는다는 표현은 설명하지 않고 제작 요구(마력석 1개 이상)로만 드러낸다. 대사·아이템 설명에 이유를 쓰지 않는다(수칙 4). 컨셉의 [구현] "마력석 등 = 마력석 1 + 고철 2"가 이미 이 설정과 맞다.
- **"지역 전용 잠금 재료 없음" 원칙의 예외:** 컨셉은 기본 재료 6종이 어느 지역에서도 나오고 지역 전용 잠금 재료가 없다는 원칙을 두었다. 마력석은 판타지 재료이고 경계지 중심이므로, 전기·기계 장비는 사실상 경계지 이후 해금이 된다. 이는 수칙 2(진행 잠금 없음)의 "메인 스토리 이탈 자유" 범위에서 허용한다(결정 15 해석). 시가지에도 마력석이 아주 소량 떨어지는지는 **[미결정]**(기본: 없음).
- **폭파장치 재료(초안 [측정])**: 고철 + 전선 + 플라스틱 + 마력석(1개 이상). 수량은 채집 밀도 실측 후 정한다. 설계도 획득과 재료 모으기의 두 단계가 해금 시점을 조절한다.
- **용도:** 던전 입구 낙반 제거. 같은 장치가 시가지 곳곳의 낙반 샛길·지름길에도 쓰일 수 있다(D-23). 폭발의 영향 범위는 낙반 오브젝트에 한정하는 것을 기본으로 한다(지형·건축물 변형과의 충돌을 피함, 결정 99의 기초 보호와 같은 취지). **[제안]**
- **폭발·불 규칙:** 폭파는 불 규칙(마소·물·불)과 연결될 수 있으나 1.0에서는 연출(소리·잔해 제거)로만 쓰고 불을 번지게 하지 않는다(규칙 조합 복잡도 관리). **[제안]**
- 위험: 폭파가 건축물·NPC·지도를 파괴할 수 있다는 인상을 주면 수칙 1·3과 충돌한다. 폭파 대상은 낙반으로 한정하고 안전 거리 규칙을 둔다. **[제안]**

### D-29. 화풍·시점 전환 (확정: 결정 108~110)
- **결정 108: 화풍·시점을 2D 픽셀 탑다운(코어 키퍼 계열)으로 전환한다.** 이유: 저사양·저비용·시간 절약·감성. 결정 22(3인칭 추격 카메라)와 3D 저폴리 전제를 대체한다. 상세·영향·새로 정할 것은 `2d-transition-impact.md`.
- **결정 109: 색조는 차분한 탁한 색 + 지역의 포인트 색만 선명하게**(시가지 회색·갈색 폐허, 경계지 보라·청록, 요정숲 저채도 녹색).
- **결정 110: 3D 전제 문서(프로토타입 D 사양서, 엔진 게이트 계획서, 엔진 비교 메모)는 삭제하지 않고 대체·보류 표시를 달아 이력으로 남긴다.**
- **무효가 되는 이전 결정/서술:** 결정 22, 3D 지형 변형 후보와 Voxel Tools 전제의 엔진 순위, D-7(카메라), 쿼터뷰 후퇴 계획. 결정 23(실내)은 재확인 필요. 월드 크기(결정 79)는 재확인 권장.

- **결정 111: 투영은 탑다운(3/4 뷰).**
- **결정 112: 타일 크기는 32px**(P0 화풍 실험에서 조정 가능).
- **결정 113: 기준 해상도는 640×360**(약 20×11타일, 1080p 3배 정수 확대).
- **결정 114: 스프라이트 방향 수는 8방향.** 제작량 증가 경고 있음(`2d-transition-impact.md` §4.1). 완화안(스프라이트 4방향 + 미러, 프레임 상한)은 필요 시 선택.

- **결정 115: 지형 변형의 2D 표현은 "빌더즈식 블록 높이"로 한다.** 타일마다 높이 값(쌓기 +1, 깎기 −1)과 절벽 타일을 쓰고, 높이 차 1은 오르고 2 이상은 막힌다. 마소 농도가 최대 높이·깊이 한계를 정하고(결정 98), 건축물 기초 보호(결정 99)는 타일 마스크로 유지한다. 상세는 `2d-transition-impact.md` §4.2. 불합격 시 A(타일 상태 전환)로 후퇴.

- **결정 116: 땅을 깎으면 흙 블록을 얻고, 쌓으면 흙 블록을 소모한다**(빌더즈식). 지형 변형이 파밍·건축 루프와 이어진다. 세부 [제안/미결정]: 흙 블록은 지형에서 얻는 별도 자원(기본 재료 6종과 별개)이며 모든 지역에서 얻을 수 있다(지역 전용 잠금 없음). 보유 한도, 죽음 시 손실 여부(재료 절반 손실 규칙에 포함할지), 시작 지역(시가지, 한계 +1/−1)에서의 총량 균형, 델타 저장과의 정합(흙 블록 보유 수는 인벤토리 세이브)은 프로토타입에서 확정한다. 총량 보존 구조이므로 같은 타일을 쌓고 깎으면 흙 블록은 늘지 않는다(깎은 만큼만 쌓을 수 있다) — 흙이 부족하면 쌓을 수 없는 제약이 생긴다.

- **결정 117: 높이 차 2 이상을 내려가는 것(낙하)은 허용하고, 올라오는 것은 막힌다.** 절벽에서 뛰어내릴 수 있다(젤다식 반점프 느낌). 갇힘 방지가 필요하다 [제안]: ① 낙하 피해 없음(절대수칙 1) ② 구덩이 안에서 인접 벽을 깎아 흙 블록을 얻고 계단을 만들 수 있다 ③ 흙·수단이 없어 완전히 갇히면 안전 복귀(가장 가까운 올라갈 수 있는 타일 또는 회복 장소, 재료 손실 없음)를 제공한다. 대형 함정·함몰(결정 74)과 같은 낙하 규칙이므로 구덩이에 빠진 대형의 탈출 규칙(무방비 후 올라옴)과 일관되게 설계한다.

- **결정 118: 변형 범위는 기본 1타일이고, 마소 농도가 상한을 열며(옅음 1타일, 짙은 곳은 십자/3×3까지 선택 가능), 미오 서브스토리 2단계 보상이 상한을 한 단계 확장한다.** 결정 21(농도가 범위·한계를 정함)과 결정 63(미오 보상: 변형 범위 소폭 확장)을 모두 만족한다. 서브스토리를 피한 플레이어도 농도가 짙은 곳에서 범위를 넓힐 수 있다. 정확한 단계(1/십자/3×3)와 확장 폭은 프로토타입에서 확정한다 **[측정]**.

- **결정 119: Godot 코드 언어는 표준 빌드(GDScript).** .NET/C#은 쓰지 않는다. Unity 게이트(2주차)에서 C#을 쓰게 되면 코드 이전 비용이 있음을 알고 간다.
- **결정 120: 픽셀 아트 도구는 Pixelorama**(무료·오픈소스). 마음에 안 들면 LibreSprite·Krita·Piskel로 바꿀 수 있고, Aseprite 같은 유료 구매는 사용자가 그때 결정한다(결정 94).
- **결정 121: 게임 프로젝트(코드·에셋)는 문서 레포와 분리한 별도 저장소에 둔다.** 이 문서 레포(`rpg-game`)는 설계 문서 전용으로 유지한다. 이 세션은 `rpg-game`만 다룰 수 있어 별도 저장소는 사용자가 만들고, 이 세션이 다루려면 저장소 접근 설정이 필요하다.

- **결정 122: 회복 장소에서 쉴 때 나오는 꿈의 소품은 "끊어진 줄(끝이 풀밭에 놓여 있음)".** 인연의 '선'(에닐 이름 암시, 인연 시스템)과 이어지는 상징이다. 직접적인 정보는 없고 결말을 알고 다시 보면 의미가 생긴다. 대사·자막 없음.
- **결정 123: 조각 8개가 모인 뒤 월드의 변화는 "랜드마크 철골에 연하게 빛이 있고 주변 풀이 자라난다."** 덧씌움(마소가 옅은 시가지에 풀이 남)과 이어진다. 알림·UI·설명 없이 변화 플래그 하나로 구현(철골 스프라이트에 빛 오버레이 + 주변 타일 풀 변화). 픽셀 아트 제작량이 적다.

- **결정 124: 폭파장치 설계도를 얻는 경계지 POI는 "잘라낸 자리 가장자리에 남겨진 공사 현장(가설물·장비)".** 현대 쪽 경계에서 공사 중이던 기자재·장비가 그대로 남은 고정 장소. 설계도는 시공자의 책상/작업판에 놓인 종이로 설명 없이 놓는다. 불나비가 지키는 영역에 가깝게 두되 위협은 불나비 수준으로 약하게 유지한다. 미오 1단계(경계 표지)와 지역은 겹치지만 퀘스트와는 무관하다(결정 86). 구체 좌표는 월드 배치 때 정한다.

- **결정 125: 제목은 가제로 두고 나중에 정한다.** 스팀 상점 페이지 공개(P3 중반 이후) 전까지 정한다. 스팀 이름 중복 여부 확인은 정할 때 한다.

- **결정 126: 사용자 PC의 Claude Code를 Remote Control로 연결해(일반 PowerShell, `claude remote-control`) 이 세션이 PC 쪽 세션을 시작하고 읽기 전용 작업부터 맡기는 방식을 쓴다.** 사용자가 이 세션의 신뢰된 기기 접근을 허용했다(되돌릴 수 없음). 수정 작업은 사용자 승인 후에만 한다. 관리자 권한 PowerShell은 쓰지 않는다. 첫 읽기 전용 점검 결과는 `gate-week1-guide.md` §11.

### D-28. 아직 결정되지 않은 것
- **측정·프로토타입 후 확정:** 월드 크기 숫자(방향은 결정 79 중간, 재확인 권장), 대형 전투방 레이아웃·무방비 시간, 폭파장치 재료 수량, 절벽 면 높이(16px vs 32px), 타일·방향·해상도 최종값(결정 112~114, P0에서 조정 가능), 변형 한계·범위 수치, 흙 블록 보유 한도·죽음 시 손실, 열쇠 부탁 보상 수량, 던전 마소 농도 구간값.
- **일정 단축 방안(D-8의 1~4 중 선택):** 프로토타입 결과 후(결정 27).
- **사용자 결정 대기:** 8GB 메모리 제한의 안전한 방식, GameMaker 유료 일회성 구매 여부(3순위 후보, 필요할 때만).
- **나중에 결정:** 제목(결정 125).
