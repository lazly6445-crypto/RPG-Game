# 엔진 게이트 측정 계획서 (P0 1~4주차)

> ⚠ **개정 필요(결정 108): 2D 전환으로 스트리밍 8km² 3D 테스트 월드, 추격 카메라 시나리오, Godot+Voxel Tools 순서, 프로토타입 D(3D) 연동이 무효다.** 합격선·안전 마진(결정 96~97)·엔진당 2주(결정 100)·가중치(결정 101)는 유지. 개정 방향은 `2d-transition-impact.md` §6.

## 3. 측정 환경

### 3.1 기준 기기 **[확정: 결정 95·96·102]**
| 항목 | 값 |
|---|---|
| 목표 | 통합 그래픽 또는 엔트리 GPU, RAM 8GB (결정 3) |
| 실제 기종 | **사용자의 현재 PC(CPU-Z 스크린샷 기준, 결정 96):** Intel Core i5-12400F(6C/12T) · DDR4 32GB(듀얼 채널) · NVIDIA GeForce RTX 3060 Ti(VRAM 8GB) · Gigabyte B660M DS3H DDR4. **저장장치는 SSD(NVMe/SATA 미확인), OS는 Windows(결정 102)** |
| 기준 대비 | 목표 최저 사양(통합 그래픽/엔트리 GPU, RAM 8GB)보다 **훨씬 강하다.** 12400F는 내장 그래픽이 없는 모델이라 통합 그래픽 환경을 이 PC에서 **직접 재현할 수 없다** |
| 근사 방법 **[제안, 결정 96]** | ① 해상도 720p·품질 최저로 측정 ② **CPU 프레임 비용과 GPU 프레임 비용을 분리해 기록**(로그 열 cpu_ms, gpu_ms) ③ 메모리를 8GB로 제한한 상태에서도 한 번 측정(운영체제 기능으로 제한 가능한지는 **미확인**, P0 1주차에 확인) ④ **안전 마진 규칙:** 이 PC에서 평균 프레임타임이 합격선의 **50% 이하**(예: 평균 33ms 합격선이면 16.5ms 이하)여야 저사양 합격으로 본다 **[가정, 근거 없음, 임의 마진]** ⑤ 통합 그래픽 실제 성능은 이 PC로는 알 수 없으므로 GPU 의존 항목(셰이더·오버드로·메모리 대역폭)은 **보수적으로 설계**하고 출시 전 베타에서 실제 저사양 사용자 피드백으로 보완한다 |
| 실제 기기 | **구하지 않는다(결정 95).** 현재 장비에서 근사 측정만 하고 근사했음을 기록한다. 합격선 근처 결과는 출시 전 베타에서 실제 저사양 기기 사용자 피드백으로 보완한다 |

기기 정보는 CPU, GPU, VRAM(공유 메모리 포함), RAM, 저장장치 종류(SSD/HDD), OS, 드라이버 버전, 해상도, 엔진 버전을 매 측정 파일의 머리말에 기록한다.

### 3.2 공통 조건
- 해상도 1080p 기본, 720p 병기 **[가정]**.
- 수직 동기화 끔(프레임타임 측정용), 별도로 켠 상태의 체감 확인.
- 빌드: 에디터 실행이 아니라 **릴리스 유사 빌드**로 측정(에디터 성능은 참고용으로만 기록).
- 측정 전 워밍업 60초, 측정 구간 5분 이상, 동일 경로를 3회 반복 **[가정]**.
- 백그라운드 프로그램 종료, 전원 계획 고성능, 노트북은 전원 연결.

### 3.3 로그 형식 (CSV) **[제안]**
`run_id, date, engine, engine_version, device, resolution, scenario, frame_idx, frame_ms, cpu_ms, gpu_ms, mem_mb, note`
- 요약 행: 평균, 99퍼센타일, 최대, 100ms 초과 히치 수, 평균 메모리, 최대 메모리.
- 모든 엔진이 같은 열을 쓴다(엔진 프로파일러에서 추출 가능한 열만 채우고 나머지는 빈칸).

## 4. 측정 항목

### 4.1 월드 스트리밍 테스트 (G1)
| 항목 | 내용 |
|---|---|
| 테스트 월드 | 단순 지형 + 저폴리 식생 인스턴싱 + 건물 더미. **8km² 이상** [가정, 결정 79: 중간의 상한 확인용] |
| 경로 | 월드를 가로지르는 고정 경로(왕복), 최고 이동 속도로 한 번 더 |
| 측정 | 평균/99퍼센타일 프레임타임, 히치 횟수, 메모리, 스트리밍 반경 안 객체 수, 로딩 지연(맨눈 팝인 포함 기록), 디스크 사용량 |
| 합격선 | 평균 33ms 이하, 99퍼센타일 50ms 이하, 100ms 초과 히치 10분에 0회 |
| 비고 | 엔진에 대형 월드 스트리밍 기본 기능이 없으면 **직접 만든 단순 청크 스트리밍**을 사용하고 구현 시간을 기록한다(G3·프로토타입 D M12의 일부) |

### 4.2 지형 변형 최소 시나리오 (G2, G5)
- 상세 시나리오·합격선은 `prototype-d-spec.md` S1~S5, S9와 M1~M9. 엔진 게이트에서는 **그 중 필수 항목만** 본다: M1(프레임타임), M2(입력 지연), M3(히치), M6(복원 일치), M7(경계 틈), M9(카메라).
- 이 항목이 불합격인 엔진은 **지형 변형 방식을 격자 블록(후보 C)으로 바꿔 한 번 더** 시도한다(공통 퇴로).

### 4.3 이터레이션 속도 (G3)
| 측정 | 방법 | 합격선 |
|---|---|---|
| 코드 수정 → 실행 | 간단한 값 하나(이동 속도)를 바꾸고 실행까지 걸린 시간 | 에디터 핫 리로드/재실행 합쳐 30초 이내 |
| 빈 프로젝트 → 빌드 | 릴리스 유사 빌드 시간 | 10분 이내 |
| 하루 내 수정 사이클 | "전투/이동 값 수정 → 5명 테스트 가능한 빌드" 한 사이클 | 하루(파트타임 3~4시간) 안에 가능 |

### 4.4 도구 왕복 (G4)
| 측정 | 방법 | 합격선 |
|---|---|---|
| 지형 편집 → 플레이 | 지형 한 구역을 수정하고 플레이로 확인 | 10분 이내 |
| 소품 배치 → 플레이 | 식생·바위·건물 더미를 배치하고 플레이로 확인 | 10분 이내 |
| 규칙 기반 산포 | 반복 배치를 규칙/스크립트로 자동화 가능한지 | 가능 여부와 소요 시간 기록 |

### 4.4a 보조 항목 (평가에 가산, 합격선 없음)
- 학습 곡선: 처음 2주 동안 막힌 횟수와 해결 시간(구현 일지).
- 문서·커뮤니티 자료의 충분성(질문에 답을 찾은 비율).
- 데이터 파일 로딩(규칙표·대사) 편의성.
- 현지화(한국어/영어) 지원 방식.

### 4.5 배포 경로 (G7)
- 릴리스 유사 빌드가 **Steam 배포 전제(스팀웍스 SDK 연동 가능)** 와 호환되는가: 공식 문서/커뮤니티 자료 확인(실제 연동은 P1 이후).
- Windows 빌드가 깨끗한 환경(개발 도구 없는 PC)에서 실행되는가.
- 빌드 용량 기준: 빈 프로젝트 빌드 크기와 월드 테스트 빌드 크기 기록.

## 5. 합격 판정과 선택 규칙

### 5.1 필수 항목 (하나라도 실패하면 불합격)
- 4.1 스트리밍: 평균 33ms 이하, 100ms 초과 히치 10분에 0회
- 4.2 지형 변형: M1, M2, M3, M6, M7, M9
- 4.3 수정 → 실행 30초 이내, 하루 내 수정 사이클 가능
- 4.4 지형 편집 → 플레이 10분 이내
- G6 라이선스: 결정 11·93·26과 충돌하지 않음

### 5.2 가산 항목 (필수 통과 후 점수 비교 **[제안]**)
| 항목 | 가중치 **[가정]** |
|---|---|
| 지형 변형 재미(prototype-d-spec M13·M14) | 3 |
| 구현 시간(M12) 짧음 | 3 |
| 던전(터널·오버행)도 같은 방식으로 다룰 수 있음 | 2 |
| 메모리·디스크 여유 | 2 |
| 학습 곡선·자료 | 2 |
| 데이터 중심 설계 편의 | 1 |
| 배포 경로 | 1 |
각 항목 0~2점으로 채점해 가중합을 계산한다. 채점 근거는 측정 로그와 구현 일지에 남긴다.

### 5.3 선택 절차
1. 엔진 1(Godot+Voxel Tools) 필수 통과 → 엔진 2(Unity)를 **같은 최소 시나리오로** 측정해 비교한다. 엔진 1 불합격이고 엔진 2 합격이면 엔진 2를 선택한다.
2. 두 엔진이 모두 필수 통과면 가산 점수 높은 쪽. 동점이면 **결정 11·93에 덜 민감한 쪽(무료·오픈소스)** 을 택한다.
3. 두 엔진이 모두 불합격이면 §7의 퇴로로 한 번 재측정한다.

## 7. 퇴로 **[제안]**

1. **지형 변형 방식 퇴로:** 불합격 시 격자 블록(C)으로 재시험(`prototype-d-spec.md` §3).
2. **월드 스트리밍 퇴로:** 직접 구현 단순 스트리밍도 불합격이면 월드를 **연결된 소규모 맵 여러 개**(로딩 화면으로 연결)로 바꾼다(`dev-roadmap.md` §2, Luban 3부). 이는 결정 79(월드 크기 중간)·기둥 2와 연결되므로 월드 구성 재검토가 필요하다.
3. **엔진 퇴로:** 엔진 2도 불합격이면 Unreal(3순위)을 같은 방식으로 측정한다. 단 지형 변형은 유료 플러그인 또는 직접 구현 전제이며 결정 11·93과 충돌 소지가 있다.
4. **전부 불합격:** `prototype-d-spec.md` §8.3의 "독자 요소 재검토"로 이동. 사용자 결정 필요.

- 이 4주는 프로토타입 D(약 8주)의 앞부분과 겹친다. 같은 최소 시나리오를 공유해 중복 작업을 피한다.
