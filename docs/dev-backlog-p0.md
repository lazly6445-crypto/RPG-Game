# 개발 백로그 (P0 자동 루프용)

> 근거: `gdd-1.0.md` §4.3(마소), §4.4·§8(몬스터), §6(월드), §7(시스템), `prototype-a-spec.md`, `prototype-d-spec.md`. 엔진 Godot 4.7.2(결정 127). 게임 코드는 PC의 `D:\gate-godot`(로컬 git, 푸시 안 함).
> **제외:** 인연·NPC·서브스토리·결말·스포일러 항목(GDD §9~§10)은 이 루프에서 만들지 않는다. 코드·씬·로그·데이터 파일에 스포일러 문구를 쓰지 않는다. 사용자의 서사 결정이 필요한 항목이기 때문이다.
> 표기: **[가정]** 임시 수치(데이터 파일에 두고 사람이 조정) · **[확인]** 사람이 직접 해 보고 판단 · **[자동]** 헤드리스 테스트로 판정 가능.

## 0. 루프 규칙
1. 항목은 번호 순서대로 한 번에 하나, 항목마다 PC 세션 1개. 세션은 구현 → 헤드리스 테스트 → 실패하면 수정(최대 5회) → 통과하면 로컬 커밋까지 한다. 푸시·삭제·설치·관리자 권한은 금지.
2. 모든 수치는 `data/*.json`, 코드는 노드 없는 순수 로직 + 얇은 씬(기존 패턴: `Terrain`, `GridMover`, `combat_sim`). 값 검증 함수 포함.
3. 항목마다 **확인 씬**을 만든다(읽을 수 있는 형태: 색 네모만 쓰지 않는다. `display_style='readable'`, 형태·방향·효과 표시). 사람이 보는 항목은 [확인]으로 표시하고, 자동 루프는 거기서 판정하지 않고 다음 항목으로 넘어간다(확인 목록에 쌓음).
4. 끝난 항목은 이 대화에서 결과를 읽어 `docs/`에 기록·푸시하고 세션을 보관한다. 실패(5회 재시도 후)하면 루프를 멈추고 원인을 보고한다.
5. 기존 테스트(test_world/terrain/rules/save_misc/combat)가 계속 통과해야 다음 항목으로 넘어간다.
6. 측정(bench)은 항목에 명시된 경우에만 한다(측정 확대 금지).

## 1. 항목 (순서)

### B5. 마소 농도 필드와 능력치 연동 [자동]
- `ManaField`: 타일 좌표 → 농도 d(0~1) 연속값. 현재 테스트 월드의 구역(x 기준 3분할)에서 옅음 0.2 / 중간 0.55 / 짙음 0.9 [가정]를 기준값으로 하고 구역 경계 8타일 구간을 선형 보간. 던전은 깊이로 0.2 → 0.9 [가정]. `Terrain`의 기존 구역 한계표(+1/−1, +3/−2, +4/−3)는 **그대로 둔다**(지형 변형 결과 불변).
- 몬스터 능력치 배율: `scale = lerp(scale_min, scale_max, d)`를 몬스터 정의별 데이터로(HP·속도·피해 각각). "판타지 존재는 옅은 곳에서 약해진다"(GDD §8): 배율은 d에 대해 비감소. 배율에 상한(`cap`).
- 테스트: d 연속성(경계 양쪽 차이 ≤ 한 칸당 기울기), 단조성, 상한, 던전 깊이 매핑, 기존 지형 한계 불변.

### B1. 몬스터 틀 + 들개 [자동 + 확인]
- 몬스터 정의 데이터(`data/monsters.json`): id, 이름, 행동 유형(behavior), hp/speed/damage 기본값, 마소 배율 범위, 감지·공격 거리, 예비동작/후딜, 영역 규칙. 기존 `combat_sim` 적은 'chaser' 유형의 기본값으로 유지(기존 테스트 통과).
- **들개(시가지, 가장 약함)**: 개 소굴(짐 더미 오브젝트)을 지킨다. 소굴에서 `leash`(10타일 [가정]) 안에서만 추격하고 벗어나면 포기하고 소굴로 복귀. 예비동작 0.3초 돌진 1회 후 후딜. 소굴 1개당 1~3마리. HP 2, 속도 70px/s, 피해 1 [가정].
- 테스트: 영역 안 추격, 영역 이탈 시 포기·복귀, 소굴당 개체 수, 마소 배율 적용(시가지는 d=0.2 → 약함), 높이 규칙(2단 벽 막힘), 처치 이벤트.
- 확인 씬: 소굴 + 개 + 영역 원(디버그 표시), 읽을 수 있는 형태.

### B2. 불나비 [자동 + 확인]
- 경계지의 "잘라낸 자리"(타일 속성 `cutout`: 한 변 5~11타일의 네모) 위에만 산다. 한 칸 물러서면(플레이어가 cutout 밖 1타일) 추격 포기. 사람보다 느림(40px/s [가정]). **서 있는 자리가 경계 표지**: 스폰 위치는 cutout 가장자리.
- 데이터: 잘라낸 자리 정의(좌표, 크기) → 타일 속성 + 땅빛(보라·청록) 표시.
- 테스트: cutout 밖으로 나가지 않음, 플레이어 이탈 시 포기, 속도 < 플레이어, 가장자리 스폰.

### B3. 가시뿌리 [자동 + 확인]
- 수풀에 돋아 **안 움직인다**. 줍는 거리(32px [가정])보다 긴 손(48px [가정])으로 곁의 잔해 한 줌을 지킨다. 접근하면 예비동작 0.5초 후 휘두름. 비켜 걸으면 끝(추격 없음). HP 3 [가정], 처치 가능.
- 의존: 줍기. B6(줍기·인벤토리) 전에 만들 때는 잔해 오브젝트를 임시 마커로 두고, 줍기 연동은 B6에서 연결(테스트에 잔해 접근 가능 여부로 판정).
- 테스트: 비켜 걸으면 피해 없음, 사거리 밖 안전, 휘두름 판정, 처치 시 잔해 접근 가능.

### B6. 줍기·재료·인벤토리 [자동 + 확인]
- 재료 7종: 판자·고철·천 조각·유리 조각·전선·플라스틱(현대 잔해 6종) + 마력석. 줍기(상호작용 키 E [가정]), 바닥 잔해(희소), 컨테이너(나무 상자·철제 사물함: 여러 번 열기 없이 1회 열면 내용물), 인벤토리(데이터: 종류별 개수, 상한 없음 [가정]).
- 마소(몸에 쌓는 양, 플레이어 한정): 마력석을 주우면 +1, 3 이상이면 몸이 빛남(발밑 밝힘) — GDD §4.3의 구현된 규칙. 표시는 단순 반경 조명.
- 테스트: 줍기 거리, 개수 증가, 컨테이너 1회성, 마소 임계값(3), 인벤토리 직렬화.
- 확인 씬: 잔해(작은 아이콘), E 줍기, 좌측 목록.

### B7. 규칙 엔진 (물·불 + 지형 변형) [자동 + 확인]
- 데이터 표(`data/rules.json`): 속성 태그 + 상태 + 자극 → 결과. 규칙 3개(마소·물·불) + 지형 변형 상한. 이 단계는 **물과 불**을 격자에서: 불은 인접 타일의 가연 태그로 번지고 시간이 지나면 꺼짐, 물은 높이가 낮은 쪽으로 흘러 고이며(파면 고이고 쌓으면 막힘) 물에 닿으면 불이 꺼지고 젖은 타일은 불이 안 붙는다. 방화선: 지형 변형(깎기)으로 가연 타일을 비우면 불이 끊김.
- 마소 × 물/불 조합은 GDD에서 미확정이므로 **"정의 안 함"**으로 표에 기록(구현하지 않음).
- 조합 매트릭스 문서(`docs/rule-matrix.md`)를 생성: 칸마다 의도한 결과 또는 "정의 안 함". 자동 시뮬레이션 테스트(고정 시드, 번짐 속도·결과 결정적).
- 테스트: 불 번짐, 물 흐름(내리막), 물이 불을 끔, 젖은 타일 면역, 방화선(깎아서 끊김), 쌓기로 물길 막힘, 결정성, 성능(타일 1만 칸 규칙 갱신 시간 기록 — 참고).
- 확인 씬: 불 붙이기/물 붓기/지형 편집 키, 잘 읽히는 표시(불꽃 색, 물 파랑 반투명, 젖음 어두움).

### B8. 죽음과 회복 장소 [자동 + 확인]
- 체력 0 → 쓰러짐 → 가장 가까운 **가 본 회복 장소**(랜드마크 철골 오브젝트)에서 깨어남, 기본 재료(6종) 절반 손실(마력석·장비·도구·설치물은 유지). 체력은 회복 장소에서만 참(붕대로 즉시 40 회복은 후속).
- 던전 모드 플래그: 던전에서 체력 0이면 입구로 되돌려지고 재료 손실 없음, 진행 상태 유지(플래그만 구현).
- 테스트: 손실 계산(홀수 개수는 올림/내림 규칙을 데이터로), 가장 가까운 방문 장소 선택, 던전 모드, 방문 기록.

### B9. 월드 블록아웃 로더 + 튜토리얼 통로 [자동 + 확인]
- 월드 정의 파일(ASCII 또는 JSON 레이어: 높이, 지역 id, 오브젝트, cutout)을 읽어 `World`/`Terrain`에 적용하는 로더. 현재 노이즈 월드와 공존(프로파일 선택).
- **튜토리얼 통로**: 두 언덕 사이 골짜기, 폭 9타일, 길이 100타일 [GDD 컨셉 수치], 길 위 잔해 6개로 걷기와 줍기를 겪게 한다(글·팝업 없음), 끝에서 시가지 맵으로 이어짐, 통로를 걸어 나오는 순간 말없이 1회 자동 저장(B10 이후 연결, 여기서는 트리거 이벤트만).
- 시가지 블록아웃: 도로·골목·실내 가능한 건물 3~5채·랜드마크(철골 회복 장소)·들개 소굴 2~3개. 크기는 [가정] 128×128 타일.
- 테스트: 로더가 정의 파일과 일치하는 높이·오브젝트를 만든다, 통로 치수, 잔해 6개, 경계 연결, 회귀(기존 테스트).

### B10. 저장 통합 [자동]
- 기존 델타 저장에 인벤토리·마소·방문 회복 장소·열린 문·진행 플래그·플레이어 위치를 추가(버전 필드와 마이그레이션 훅). 자동 저장 트리거(통로 출구).
- 테스트: 별도 프로세스 복원 해시 일치, 버전 불일치 거부, 손상 파일 거부.

### B11. 건축 + 실내 + 변형 불가 영역 [자동 + 확인]
- 판자 바닥·벽·문 설치(조리법 데이터), 설치물 충돌, 실내 판정(문 포함 벽으로 둘러싼 칸), 부수기(조리법 절반 환급), 기초 보호(기존 마스크 연동), 실내 진입 시 지붕 페이드.
- 테스트: 재료 소모, 충돌, 실내 판정 케이스, 환급, 마스크 연동.

### B12. 던전 + 적대적인 존재 + 대형(문지기) [자동 + 확인]
- 입구 낙반(설계도로 만든 도구 필요; 도구는 폭파장치 등 데이터 정의, 마력석 기초 재료 규칙 적용), 깊이별 마소 d, 적대적인 존재 A/B/C(데이터: 형체 불분명한 그림자 형태, 사람을 노림, 영역 한계 던전 안에서만), 대형 1종: 기존 `PitTrapDummy`를 실제 대형 적으로 승격(경로 이동, 함정·함몰 공략, 무방비 8초 [가정]), 대형 전투방 변형 가능 지면.
- B1~B8과 B11 이후 진행. 세부 수치는 이 항목 시작 전에 사용자 확인.

## 2. 사람이 확인할 목록 (자동 루프가 쌓는다)

## 3. 루프 정지 조건

- 사용자 결정이 필요한 지점(수치가 아니라 설계 선택: 예 B12 세부, 서사 관련).
- 사용자가 PC를 쓰는 중이라고 알린 경우(창이 뜨는 측정은 하지 않으므로 대부분 영향 없음).
- 사용 한도 경고.
