## 1. 목적과 질문

**목적:** 독자 요소인 "땅을 쌓고 깎는다"가 이 프로젝트의 제약(1인·파트타임, 최저 사양 통합 그래픽/엔트리 GPU·RAM 8GB·30fps, 저장 자유)에서 **감당 가능한지**, 재미있는지 판정한다. 판정 결과는 엔진 게이트(P0 4주차)와 일정 단축 방안 결정(결정 27)의 입력이다.

**답해야 할 질문**
| # | 질문 | 판정에 쓰는 증거 |
|---|---|---|
| Q1 | 변형 입력 → 화면 반영까지 지연이 감당 가능한가? | 입력-반영 지연, 변형 중 프레임타임 |
| Q2 | 변형 결과 저장(델타)과 불러오기가 용량·시간 면에서 감당 가능한가? | 변형 N곳 저장 용량·로드 시간 |
| Q3 | 스트리밍 경계에서 변형이 일관되는가(틈·튕김 없음)? | 경계 시나리오 시각 검사·로그 |
| Q4 | 충돌·내비게이션 갱신 비용은? 캐릭터가 변형 직후에도 자연스럽게 서 있는가? | 변형 직후 플레이어/적 이동 테스트 |
| Q5 | 마소 농도가 변형 범위·내구를 정하는 규칙(결정 21)이 구현 가능하고 재미있는가? | 농도 3단계 비교 플레이 |
| Q6 | 건축물(판자 바닥·벽·문)과 변형이 충돌하지 않게 규칙을 정할 수 있는가? | 건축물 주변 변형 시나리오 |
| Q7 | 대형 전투방의 함정·함몰 공략(결정 74)이 성립하는가? | 구덩이에 빠뜨리는 샘플 전투 |
| Q8 | 3인칭 추격 카메라가 변형 직후/좁은 공간에서 버티는가? | 카메라 시나리오 |
| Q9 | 이 방식을 1인이 구현·유지할 수 있는 복잡도인가? | 구현 일지(소요 시간, 막힌 지점) |

## 2. 범위

### 2.1 포함
- 지형 변형 입력(쌓기·깎기), 변형 범위 조절, 마소 농도에 의한 범위·한계 배율
- 델타 저장/불러오기(원본 지형은 읽기 전용)
- 스트리밍 경계에서의 변형 시나리오(최소 2개 청크/셀)
- 건축물 주변 변형 규칙 테스트(건축 시스템 전체가 아니라 **판자 바닥·벽 더미 오브젝트**만)
- 대형 전투방 샘플(변형 가능한 지면, 구덩이에 빠지는 더미 대형 적)
- 3인칭 추격 카메라(프로토타입 A·C와 공용 가능)
- 최저 사양 측정 환경에서의 실행

### 2.2 제외 (이 프로토타입에서 하지 않는다)
- 최종 아트·셰이더·VFX(색은 지역별 구분용 임시 팔레트만)
- 퀘스트, 대사, UI 디자인, 인벤토리·제작
- 물·불 규칙(프로토타입 B 소관). 단, **물 × 지형 변형** 조합은 결정 20·D-6의 퇴로 판정을 위해 §7에서 최소 한 시나리오만 본다
- 지도와의 연동(결정 71: 연동하지 않음)
- 멀티스레드 최적화·플랫폼별 최적화(문제가 발견된 곳만)

## 3. 변형 방식 후보와 결정 절차

GDD §7.2의 후보 3가지. 엔진 게이트(`engine-comparison-memo.md` §6)와 함께 선택한다. 모든 후보가 아래 §4~§8의 같은 시나리오·합격선으로 비교된다.

| 후보 | 요지 | 이 게임에서의 장점 | 위험 |
|---|---|---|---|
| A 높이맵 편집 | 격자 높이 값을 올리고 내림 | 단순, 저비용 | 동굴·오버행 불가 → 던전 터널·대형 전투방 함정 표현에 제약 |
| B 복셀/청크 | 3D 볼륨을 청크 단위로 편집 | 오버행·터널, 던전과 필드를 같은 방식으로 다룸 | 메모리·메시 생성 비용, 델타 저장 설계, 경계 틈 |
| C 격자 블록 | 일정 크기 블록 단위로 쌓고 깎음 | 저폴리 화풍과 궁합, 델타 저장 단순, 엔진 독립 퇴로 | 부드러운 지형이 아님(화풍으로 소화), 블록 수 증가 시 비용 |

**결정 절차 [제안]**
1. 엔진 게이트 1~2주차: 엔진당 **가장 현실적인 후보 1개**로만 최소 시나리오(§4의 S1~S3)를 만든다.
2. 합격선(§8)을 통과하는 후보가 둘 이상이면 §9의 우선순위로 고른다.
3. 모두 불합격이면 **후보 C(격자 블록)** 로 최소 구현해 §8을 다시 판정한다. C도 불합격이면 변형 범위를 축소한다(§11 퇴로).

## 4. 시나리오

모든 시나리오는 3인칭 추격 카메라로 플레이어가 직접 조작해 수행한다.

| ID | 시나리오 | 무엇을 보는가 | 질문 |
|---|---|---|---|
| S1 | **기본 쌓기·깎기:** 평지에서 1×1 지점을 쌓고 깎는다. 범위를 바꿔 반복한다 | 입력-반영 지연, 프레임타임, 충돌 갱신 | Q1, Q4 |
| S2 | **다리 만들기:** 두 절벽 사이에 땅을 쌓아 건넌다 | 쌓은 지형 위를 걸을 수 있는가, 카메라가 버티는가 | Q4, Q8 |
| S3 | **벽 쌓아 오르기:** 쌓아서 높은 곳에 오른다(경사·단차 규칙) | 이동 규칙(점프·오르기)과의 상호작용 | Q4, Q8 |
| S4 | **저장·불러오기:** 변형 N곳(§6) 후 저장 → 종료 → 불러오기 | 용량, 시간, 복원 일치 | Q2 |
| S5 | **스트리밍 경계:** 청크/셀 경계를 걸쳐 변형하고, 경계 밖으로 이동했다 돌아온다 | 틈, 겹침, 델타 유실 | Q3 |
| S6 | **마소 농도 3단계:** 옅음/중간/짙음 세 구역에서 같은 입력으로 변형 | 범위·한계 배율 차이가 체감되는가 | Q5 |
| S7 | **건축물 인접:** 판자 바닥·벽 더미 주변과 아래를 깎거나 쌓는다 | 규칙(§5.4)에 맞게 막히거나 처리되는가 | Q6 |
| S8 | **대형 전투방 샘플:** 더미 대형 적이 정해진 경로로 걷고, 플레이어가 경로에 구덩이를 파면 빠진다. 일정 시간 무방비 | 구덩이 판정, 적 경로 AI와 변형 충돌, 탈출 규칙 | Q7 |
| S9 | **좁은 공간:** 변형으로 만든 좁은 통로·벽 사이에서 카메라 | 카메라 충돌, 시야 가림 | Q8 |
| S10 | **(퇴로 판정용) 물 × 지형 변형:** 물을 흉내 낸 단순 높이 규칙(웅덩이가 낮은 곳에 고임)으로 파면 고이고 쌓으면 막힘을 한 번만 | 물을 넣을 여지가 있는가 | 퇴로 |

## 5. 기능 사양

### 5.1 변형 입력 **[제안]**
- 두 모드: **쌓기**, **깎기.** 범위(반경) 단계는 3단계(작음/중간/큼) **[가정]**.
- 입력은 겨눈 지점에 대해 즉시 반영한다. 길게 누르는 연속 변형은 선택 사항(S1에서 두 방식 모두 시험해 고른다) **[측정]**.
- 변형 가능한 사거리는 플레이어 전방 일정 거리(카메라와 무관) **[가정]**. 구체 수치 **[측정]**.
- 입력 장치·키는 정하지 않는다(P1 UX에서 확정, 키 리매핑 대상).

### 5.2 마소 농도 맵 (결정 21, 50, 51, 72) **[제안]**
- 지역 농도는 저해상도 격자 맵 한 장(값 0~1의 연속값). 프로토타입에서는 **3단계 구역(옅음 0.1 / 중간 0.5 / 짙음 0.9)** 만 테스트한다 **[가정]**.
- 농도는 지역 고정값이다(플레이어 행동으로 변하지 않음, 결정 51).
- 던전은 깊이에 따라 값이 기울어진다(결정 72). 프로토타입에서는 S8 대형 전투방을 "짙음" 구역으로 둔다.
- **농도 → 변형 파라미터 배율** (곡선은 모두 **[측정]**):
  | 파라미터 | 옅음 | 짙음 | 비고 |
  |---|---|---|---|
  | 한 번에 변형되는 반경 배율 | 0.5배 | 1.5배 | 선형 보간 |
  | 깎을 수 있는 최대 깊이 | 작음 | 큼 | |
  | 쌓을 수 있는 최대 높이 | 낮음 | 높음 | |
  | 쌓은 지형의 지속(내구) | 아래 5.2.1 | | |

#### 5.2.1 "내구"의 정의 **[미결정]**
결정 21은 "농도가 변형 범위·내구를 정한다"고만 말한다. 구현 방식이 둘로 갈린다. 둘 다 프로토타입에서 시험한다.
| 안 | 내용 | 장점 | 위험 |
|---|---|---|---|
| ㄱ 최대 한계 | 내구 = 쌓을 수 있는 최대 높이/깎을 수 있는 최대 깊이(영구) | 저장 단순, 수칙 3(저장 자유)과 충돌 없음 | "오래간다"는 느낌이 약함 |
| ㄴ 시간 침식 | 옅은 곳에서 쌓은 지형이 시간이 지나면 점차 원래 지형으로 복귀 | 농도 차이가 분명히 체감됨 | 침식 시각이 세이브에 의존, 되돌려도 결과가 같아야 한다는 수칙 3 정신과 어긋날 수 있고, 건축물/서브스토리 중 지형이 사라질 위험 |
**기본안: ㄱ(최대 한계).** ㄴ은 S6에서 "체감 차이가 필요한가"를 보고 결정한다. 사용자 결정이 필요하다 **[미결정]**.

### 5.3 델타 저장 **[제안]**
- 원본 지형은 읽기 전용. 변형은 **차이만** 저장한다.
- 저장 단위: 청크/셀 단위로 변경 목록을 모으고, 변경이 없는 청크는 저장하지 않는다.
- 세이브 파일에는 지도 데이터를 넣지 않는다(결정 71). 세이브에 버전 필드와 마이그레이션 훅을 둔다(P1-8).
- 불러오기 시 원본을 먼저 로드한 뒤 델타를 적용한다. 적용 중 보이는 지형이 "튀지" 않게 청크 단위로 적용한다 **[측정]**.
- **합격선(§8)에 쓰는 저장 시나리오:** 서로 다른 청크에 걸친 변형 100곳 후 저장 → 새 프로세스에서 불러오기.

### 5.4 건축물과의 규칙 **[제안]**
건축 시스템은 컨셉의 판자 바닥·벽·문, 실내 판정(문 포함 벽으로 둘러싼 칸), 부수기. 지형 변형과 충돌하는 경우를 다음 3안에서 시험한다.
| 안 | 규칙 | 장점 | 위험 |
|---|---|---|---|
| ㉠ 기초 보호 | 건축물 바닥 면 + 여유 1칸은 변형 불가(표시) | 구현 가장 쉬움, 예측 가능 | 지형 변형 자유가 줄어듦, 표시 UI 필요 |
| ㉡ 기초 따라 이동 | 건물 아래 지형이 변형되면 건축물이 허공이 되지 않게 건축물 높이를 지형에 맞춤 | 자유도 높음 | 복잡, 경계 케이스 많음 |
| ㉢ 붕괴 | 건물 아래를 깎으면 건축물이 부서진다 | 규칙이 직관적, 제작 부담 낮음 | 플레이어 작품 손실이 수칙 1·3(난이도/저장 자유)과 충돌 소지 |
**기본안: ㉠(기초 보호).** 가장 단순하고 1인 개발 부담이 낮다. S7에서 ㉠~㉢ 중 최소 ㉠을 필수로 구현하고, ㉡·㉢은 ㉠이 불합격일 때만 시험한다.

### 5.5 대형 전투방 샘플 (S8, 결정 69·73·74) **[제안]**
- 방은 **짙음 구역**(결정 72: 심부). 변형 가능한 지면이 방 대부분을 차지한다.
- 더미 대형 적: 고정 경로(직선 또는 원형)를 걷는다. 전투 AI는 만들지 않는다.
- 구덩이 판정: 깊이/폭이 임계 이상이면 적이 빠진다 **[측정]**. 빠진 뒤 **무방비 시간**(초기값 8초 **[가정]**, 낮은 난이도에서는 더 길게) 동안 플레이어가 공격할 수 있다. 시간이 지나면 탈출하며, 탈출 연출은 단순(순간이동 아님, 올라오는 애니메이션은 제외).
- 구덩이를 메우는 적 행동은 이번에 만들지 않는다.
- 측정: 구덩이 판정 오류율, 적이 지면에 낀 사례, 변형 직후 경로 갱신 비용.

### 5.6 카메라 **[제안]**
- 3인칭 추격 카메라(어깨 뒤 고정 거리 + 지형·벽 충돌 보정).
- 변형 직후 카메라가 지형 안에 들어가거나 튕기지 않아야 한다.
- 좁은 통로(S9)에서 시야가 가려지면 카메라가 가까워지거나 지형이 반투명해진다 **[측정]**.

## 6. 측정 항목과 합격선

> 모든 합격선은 **[가정]**이며 최저 사양 기기(또는 동등 제한)에서의 측정 기준이다. 측정 환경은 §7. 합격선은 프로토타입 시작 전에 사용자가 조정할 수 있다.

| ID | 측정 | 방법 | 합격선 **[가정]** | 질문 |
|---|---|---|---|---|
| M1 | 평균/99퍼센타일 프레임타임(변형 중) | S1·S2 중 프레임 로그 | 평균 33ms 이하(30fps), 99퍼센타일 50ms 이하 | Q1 |
| M2 | 입력-반영 지연 | 입력 시각 → 지형 메시 갱신 시각 | 100ms 이하 | Q1 |
| M3 | 이동 중 히치 횟수 | S5 반복 이동 | 10분 이동에 100ms 초과 히치 0회 | Q3 |

### 6.1 테스터
- 최소 3명(가족·지인 가능). 설명 없이 키만 알려 주고 5분 자유 플레이 후 질문 3개: ① 무엇을 했는가 ② 어떤 점이 재미/불편했는가 ③ 땅을 파고 쌓는 걸로 해 보고 싶은 것은.
- 결과는 기록하되 공개 UI/대사는 만들지 않는다. 반전/스포일러 문구는 테스트용 텍스트에 쓰지 않는다.

## 7. 측정 환경 **[제안]**

- **기준 기기:** 통합 그래픽 또는 엔트리 GPU, RAM 8GB. 실제 기종은 Steam 하드웨어 조사 후 결정(결정 3). 기종이 없으면 현재 장비에서 **해상도·품질 제한 또는 외부 도구로 CPU/GPU 사용률 제한**으로 근사하고, 근사했다는 사실을 결과에 기록한다.
- 해상도 1080p 기본(저사양 기준 720p 병기) **[가정]**.
- 프로파일링: 엔진 내장 프로파일러 + 프레임 로그 파일.
- **테스트 월드 규모**(S5 스트리밍용): 8km² 이상 **[가정]**, 단순 지형 + 식생 인스턴싱 더미. 실제 월드 크기(결정 79: 중간)를 정하기 위한 상한 측정용이다.
- 로그는 CSV로 남겨 후속 단계와 비교할 수 있게 한다.

## 8. 합격 판정과 다음 행동

### 8.1 후보별 판정
- **합격:** M1~M11 중 M1·M2·M3·M6·M7·M9·M11을 모두 만족하고, M4·M5·M8·M10에서 합격선 1.5배 이내.
- **조건부 합격:** 필수 항목은 만족하나 M4·M5 또는 M10이 합격선 초과. 최적화 가능성 또는 범위 축소로 해소 가능.
- **불합격:** 필수 항목 중 하나라도 실패.

### 8.2 우선순위 (둘 이상 합격 시) **[제안]**
1. 결정 11·93과 충돌하지 않는 후보(무료/직접 구현)
2. 구현 시간(M12)이 짧은 후보
3. 던전(터널·오버행)을 같은 방식으로 다룰 수 있는 후보(B > C > A)
4. 재미(M13·M14)

### 8.3 결과별 다음 행동
| 결과 | 행동 |
|---|---|
| 한 후보가 합격 | 그 후보로 확정. 엔진 게이트 판정 입력으로 사용 |
| 조건부 합격 | 최적화 한 번 시도(1주 상한). 해소되면 확정, 아니면 §11 퇴로 |
| 전부 불합격 | 퇴로(§11)로 변형 범위 축소 후 재측정. 그래도 불합격이면 **독자 요소 자체를 재검토**(사용자 결정 필요): 지형 변형 → 건축 시스템 중심으로 축소 |
| 재미(M13·M14) 낮음 | 기능이 성립해도 재미가 없으면 독자 요소 자체를 재검토. 사용자 결정 필요 |

## 11. 퇴로 (변형 범위 축소) **[제안]**
순서대로 시도하고 각 단계마다 §6 항목을 다시 측정한다.
1. 전 지형 자유 변형 → **격자 블록 단위** 변형
2. 격자 블록 → **지정 구역(변형 가능 영역)만** 변형: 시가지/경계지/요정숲 일부, 던전 대형 전투방, 미오 서브스토리 길 구간
3. 지정 구역 변형도 불가 → **독자 요소 재검토**(사용자 결정). 이 경우 미오 서브스토리 2단계(길 쌓기)와 던전 대형 공략(함정·함몰)의 메카닉을 대체해야 한다(`dev-spec-phases.md` D-11, D-22).
- 물 × 지형 변형 조합이 구현 불가이면 **물을 빼고 마소·불 2개로 줄인다**(GDD §7.3). 이는 이 프로토타입이 아니라 프로토타입 B와 함께 판정한다.
