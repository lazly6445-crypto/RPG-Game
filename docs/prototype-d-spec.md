# 프로토타입 D 사양서 — 지형 변형 (2D 픽셀 탑다운 개정판)

> 개정(결정 108, 2D 픽셀 탑다운 전환): 3D 판(높이맵·복셀·격자 블록, 3인칭 카메라)을 대체한다. 이전 판은 git 이력에 있다.
> P0 프로토타입 D(`dev-spec-phases.md` P0-3 D, `gdd-1.0.md` §7.2·§7.3). 규칙의 출처는 결정 115(빌더즈식 블록 높이), 98(최대 한계), 99(기초 보호), 71(지도 미반영), 74(대형 함정·함몰), 21·50·51·72(마소 농도).
> **엔진 게이트(`engine-gate-plan.md`) T1~T8과 같은 시나리오를 쓴다.** 이 문서는 그 시나리오의 상세 사양이고, 게이트가 엔진 선택을 위한 *최소* 구현이라면 이 프로토타입은 *선택된 엔진*에서 재미까지 판정하는 확장판이다. 엔진 독립으로 쓴다.
> 표기: **[확정]** 사용자 결정 · **[제안]** 제안 · **[가정]** 임시값 · **[측정]** 이 프로토타입이 측정해 확정할 값 · **[미결정]** 사용자 결정 필요.

## 1. 목적과 질문

**목적:** 독자 요소인 "땅을 쌓고 깎는다"를 2D 타일 + 높이 값 + 절벽 타일로 구현해 (1) 감당 가능한지, (2) 높이가 화면에서 읽히는지, (3) 재미있는지 판정한다. 결과는 엔진 확정(게이트), 일정 단축 방안(결정 27), 독자 요소 유지 여부의 입력이다.

| # | 질문 | 판정 증거 |
|---|---|---|
| Q1 | 변형 입력 → 화면·충돌 반영 지연과 연속 편집 프레임타임이 감당 가능한가? | `edit_latency_ms`, 프레임 로그 |
| Q2 | 변경 타일 델타 저장·불러오기가 용량·시간·복원 일치 면에서 감당 가능한가? | 저장 용량·시간, 해시 일치 |

| Q4 | 높이 차 이동 규칙(1은 오르고 2 이상은 막힘)이 8방향 이동·충돌에서 안정적인가? | 이동 시험 |
| Q5 | **절벽이 화면에서 높이로 읽히는가**(탑다운 3/4 뷰)? 오토타일 규칙을 감당 가능한 비용으로 만들 수 있는가? | 가독성 시험, 구현 시간 |

## 2. 범위

### 2.1 포함
- 타일 높이 값, 쌓기(+1)/깎기(−1) 입력, 마소 농도별 한계(+범위)
- 절벽 타일 자동 표시(오토타일), 높이 차 이동·충돌 규칙, 8방향 이동
- 델타 저장/불러오기, 타일 청크 경계 시나리오
- 건축물 더미(판자 바닥·벽)와 기초 보호 마스크
- 대형 더미 적(경로 이동, 구덩이 낙하, 무방비 시간)
- 픽셀 퍼펙트 렌더(640×360, 32px 타일), 스크롤 카메라
- 최소 스프라이트(플레이어·대형 더미: 방향별 정지 이미지 또는 간단 프레임)

### 2.2 제외
- 최종 아트·VFX, 퀘스트·대사·UI 디자인·인벤토리·제작(단, 쌓기/깎기 입력과 한계 표시는 임시 디버그 표시 가능)
- 물·불 규칙(프로토타입 B 소관). 단 물 × 높이 규칙은 퇴로 판정을 위해 §4의 S10에서 한 번만 본다
- 지도 연동(결정 71: 지도는 원본 지형 기준이라 구현하지 않음)
- 몬스터 AI 전체(대형 더미 경로만), 전투 판정(프로토타입 A 소관)
- 멀티스레드·플랫폼 최적화(문제가 발견된 곳만)

## 3. 규칙 사양 (테스트 대상) **[확정: 결정 115 등 / 세부 [제안]]**

### 3.1 높이 값
- 타일마다 정수 **높이 값 h**(원본 지형의 높이는 읽기 전용, 변형량 Δh를 별도로 저장). 현재 높이 = 원본 + Δh.
- 쌓기: Δh +1, 깎기: Δh −1. 한 번의 입력은 한 단계.
- **한계(내구, 결정 98):** Δh의 범위는 마소 농도 단계가 정한다. 초기값 [가정, 측정]:
  | 농도 | 지역 | 쌓기 한계(+) | 깎기 한계(−) |
  |---|---|---|---|
  | 옅음 | 시가지 | +1 | −1 |
  | 중간 | 경계지 | +3 | −2 |
  | 짙음 | 요정숲 | +4 | −3 |
  던전은 깊이에 따라 짙어진다(결정 72). 이 프로토타입에서는 대형 전투방을 "짙음"으로 둔다.
- **범위(결정 21):** 한 번의 입력이 영향을 주는 타일 수가 농도에 따라 다르다. 초기안 [가정]: 옅음 1타일, 중간 1타일(십자 확장 가능), 짙음 3×3까지(입력으로 1/십자/3×3 단계 선택). 범위 규칙의 선택(§10-3)은 **[미결정]**.
- 시간 침식 없음(결정 98).

### 3.1a 흙 블록 **[확정: 결정 116, 세부 [제안]]**
- **깎기 −1: 흙 블록 +1 획득. 쌓기 +1: 흙 블록 −1 소모.** 흙 블록이 0이면 쌓을 수 없다(입력이 막히고 임시 표시).
- 총량 보존: 같은 위치를 쌓고 깎는 것만으로는 흙 블록이 늘지 않는다. 늘리려면 지형을 더 깎아야 한다(마소 농도 한계 안에서).
- 흙 블록은 지형에서 얻는 별도 자원이며(기본 재료 6종과 별개), 어느 지역에서도 얻을 수 있다.
- 보유 한도 [가정, 측정]: 예 99. 죽음 시 손실(재료 절반 규칙에 포함할지)·던전 퇴장 시 손실(없음 규칙에 따름)은 프로토타입 후 확정 **[미결정]**.
- 시작 지역(시가지, 한계 +1/−1)에서는 깎을 수 있는 깊이가 −1이라 흙 블록 총량이 적다. 초반 지형 변형이 막히지 않는지 S6·S3에서 확인한다 [측정].
- 디버그 표시: 흙 블록 보유 수를 임시 숫자로 표시. 최종 UI는 P1.

### 3.2 절벽 표시 (탑다운 3/4 뷰) **[제안, 아트 실험 필요]**
- 인접한 두 타일의 높이 차가 있으면 **높은 타일의 아래쪽(남쪽, 화면 아래) 경계에 절벽 면 타일**을 그린다. 북·동·서 경계는 얇은 가장자리(턱) 표현으로 둔다(3/4 뷰의 관례).
- 절벽 면의 높이(화면에서 차지하는 픽셀): 높이 차 1단계당 **16px 또는 32px** — **[측정]**(가독성·타일 일관성 비교).
- 오토타일 케이스: 4방향 가장자리 + 모서리(안/바깥) + 단차 2 이상 연속. 엔진 오토타일 기능 또는 스크립트로 구현하며 구현 방식과 소요 시간을 기록한다(게이트 §4.4).
- 같은 타일 위의 캐릭터·오브젝트는 y 정렬로 그린다(높은 타일 위가 뒤에 가려지지 않도록 레이어 규칙 필요). **[측정]**

### 3.3 이동·충돌 (8방향) **[제안]**
- 현재 타일과 이동할 타일의 높이 차 |Δ| ≤ 1: 이동 가능(자동으로 오른다/내려선다). |Δ| ≥ 2: 막힘(양방향).
- 대각 이동은 두 인접 직교 타일이 모두 통과 가능해야 허용(모서리 끼임 방지). **[측정]**
- 변형 직후 충돌 갱신은 3프레임 안에 반영된다.
- 내려가기(낙하) 규칙: **[미결정]**(§10-2). 기본안: 높이 차 ≥ 2는 양방향 막힘.
- 몬스터·NPC도 같은 규칙을 쓴다(경로 탐색이 높이 차 규칙을 반영하는지 시험).

### 3.4 건축물 기초 보호 (결정 99) **[제안]**
- 건축물(판자 바닥·벽·문 더미)은 **평지(높이 차 0인 구역)** 에서만 지을 수 있다.
- 건축물 발자국 + 여유 1타일은 **변형 불가 마스크**. 마스크 안에서는 쌓기/깎기 입력이 막히고, 막힘 표시(예: 빗금 오버레이)를 임시로 보여 준다.
- 마스크는 건축물을 부수면 사라진다.

### 3.5 델타 저장 (결정 71 분리) **[제안]**
- 원본 지형 타일 맵은 읽기 전용. 변경된 타일만 `(x, y, Δh)` 목록으로 저장한다.
- 청크 단위로 묶고 변경이 없는 청크는 저장하지 않는다. 세이브에 `version` 필드와 마이그레이션 훅을 둔다.
- 이론적 최소 크기(좌표 int16×2 + Δh int8 = 5바이트, 압축·헤더 제외): **1000곳 = 약 5KB**. 실측은 헤더·청크 구조 오버헤드를 포함한다.
- 불러오기 순서: 원본 로드 → 청크별 델타 적용 → 절벽 타일 재계산 → 충돌 갱신. 적용 중 화면 깜빡임이 없도록 청크 단위로 적용 **[측정]**.
- 세이브에 지도 데이터를 넣지 않는다.

### 3.6 대형 함정·함몰 (결정 74) **[제안]**
- 대형 더미는 고정 경로(직선/원)를 걷는다. 이동 시 높이 규칙을 따르되 **구덩이(Δh ≤ −1 타일, 즉 경로 높이보다 1 이상 낮은 타일)에 진입하면 빠진다.**
- 빠지면 무방비 상태 **8초 [가정, 측정]** (낮은 난이도에서는 더 길게). 이후 탈출해 구덩이 가장자리로 올라온다. 탈출 연출은 단순(순간이동 아님).
- 구덩이를 메우는 적 행동은 이번에 만들지 않는다.
- 대형 전투방은 변형 가능 지면 비율이 높고 마소 "짙음" 구역으로 둔다.

## 4. 시나리오 (게이트 T1~T8과 매핑)

모든 시나리오는 640×360 픽셀 퍼펙트, 8방향 이동으로 플레이어가 직접 수행한다.

| ID | 시나리오 | 게이트 | 질문 |
|---|---|---|---|
| S1 | **기본 쌓기·깎기:** 평지에서 한 타일을 쌓고 깎는다. 절벽 오토타일 갱신, 반복·연속 입력 | T1 | Q1, Q5 |
| S2 | **이동 규칙:** 높이 차 1을 오르고 2 이상은 막힘. 8방향·대각 시험 | T2 | Q4 |
| S3 | **다리·계단 만들기:** 높이 차 2 이상 구덩이/절벽을 쌓아 건너기(미오 2단계 상당) | T3 | Q4, Q5 |
| S4 | **델타 저장·불러오기:** 변경 1000곳 → 저장 → 종료 → 불러오기 → 해시 비교 | T4 | Q2 |
| S5 | **청크 경계 편집:** 경계를 걸친 쌓기·깎기, 청크 언로드/재로드 후 복원 | T5 | Q3 |

| S8 | **대형 구덩이 함정:** 더미 대형 경로에 구덩이를 파서 빠뜨림, 무방비 시간, 탈출 | T8 | Q8 |

### 4.1 테스트 맵 사양 **[가정]**
- 크기 128×128 타일(게이트의 1024×1024 월드와 별도). 3개 구역(옅음/중간/짙음) 각 약 40×40, 청크 경계 시험용 32×32 타일 청크 선을 의도적으로 가로지르는 영역, 더미 건물 3개, 대형 전투방 24×16 타일(짙음).
- 지역 땅빛은 임시 팔레트(회·갈색 / 보라·청록 / 저채도 녹색)로 구분만 한다(결정 109).

## 7. 퇴로 **[제안]**
1. 블록 높이 방식 불합격 → **타일 상태 전환(A)**.
2. A도 불합격 → 변형 가능 영역을 **지정 구역**으로 축소: 미오 서브스토리 길 구간, 대형 전투방, 시가지·경계지 일부.
3. 지정 구역도 불가 → **독자 요소 재검토**(건축 중심 축소). 이 경우 미오 서브스토리 2단계(길 쌓기)와 던전 대형 공략(함정·함몰)의 메카닉을 대체해야 한다(`dev-spec-phases.md` D-11, D-22).
4. 물 × 높이가 구현 불가이면 물을 빼고 마소·불 2개로 줄인다(GDD §7.3). 프로토타입 B와 함께 판정.

## 10. 미결정 (사용자 결정)
1. ~~흙 블록 시스템~~ **해결(결정 116): 깎으면 흙 블록을 얻고 쌓으면 소모.** 남은 세부(보유 한도·죽음 시 손실)는 프로토타입 후 확정.

4. **절벽 면 높이:** 16px vs 32px는 측정(M17)으로 정한다.
