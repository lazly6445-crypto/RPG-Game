## 1. 설계 기둥 (조사에서 도출한 제안)

1. **곱셈형 규칙**: 소수의 일관된 규칙(예: 불·물·바람·전기, 무게·부력)을 월드 전체에 곱해 해법이 하나로 고정되지 않게 한다. Z 2장 수칙 2, Z 3.11. 소규모 팀에 가장 큰 효율을 주는 기둥이다. **[제안]**
2. **밀도 > 크기**: 작고 조밀한 월드. Z 수칙 4, R 4.4(스타필드 비판). **[제안]**
3. **환경이 안내한다**: 삼각형 지형, 랜드마크 빵 부스러기, 마커 최소화. Z 3.11, 수칙 1. **[제안]**
4. **저폴리곤을 제약이자 정체성으로**: 에셋 제작 회전이 빠르고 구형 하드웨어에서도 돌아간다(발헤임 CEO 발언, R B.6). 오카미처럼 기술 제약을 정체성으로 전환한다(ZL 8장 5). **[제안]**
5. **독자 핵심 요소 1개**: 젤다류는 구조만 닮으면 "복제" 평가를 받는다(ZL 7장). 핵심 규칙 중 하나는 이 게임만의 것이어야 한다. **[제안, 내용 미정]**

## 2. 엔진 의견 (질문: 젤다 기법 + 발헤임식 저용량 그래픽)

**결론: Unity를 1순위로 두고, Phase 0의 4주 게이트에서 실측해 확정한다. 2순위는 Godot, 3순위는 Unreal.** 이는 의견이며, 아래 표의 판단 근거 중 R에서 확인된 것과 아닌 것을 구분했다.

| 기준 | Unity | Godot | Unreal 5 |
|---|---|---|---|
| 저폴리곤·저사양 목표와의 궁합 | 좋음 | 좋음 | 나나이트·루멘 등 장점이 저폴리곤에서는 대부분 쓰이지 않고 빌드·요구사양이 무거움 (R 13.3, C) |
| 소규모 팀 생산성 | 1~5명 상업 사례 언급 있음 (R 13.3, C) | 무료·단순, 3D는 최적화에 손이 더 감 (R 13.3, C) | 학습 곡선·복잡성이 소규모 팀 생산성을 깎을 수 있음 (R 13.3, C) |
| 대형 월드 스트리밍 | 직접 구축/에셋 활용 필요, **R에 조사 없음** | 직접 구축 필요 가능성 높음, **R에 조사 없음** | 월드 파티션 공식 지원 (R 13.1, A) |
| 지형·식생 배치 도구 | 지형 시스템 있음, **R에 조사 없음** | 약함(추정), **미확인** | 있음 |
| 참고 사례 | 발헤임이 Unity라는 사실은 **R에 기재 없음, 확인 필요** | 카세트 비스트(R 13.3) | 다수 |

판단 이유(**[제안]**):
- 젤다식 기조의 핵심은 렌더링이 아니라 **자체 게임플레이 시스템**(화학·물리 규칙, 상황별 A 버튼, 주목 카메라)이다. 이는 코드 생산성과 이터레이션 속도가 좌우한다(R 13.4: 기능 목록보다 숙련도와 이터레이션 속도로 고른다).
- 저폴리곤이면 Unreal의 대표 강점이 가려지고 단점(무거움)만 남는다.
- 대형 월드 스트리밍은 Unity/Godot 모두 직접 짜야 할 수 있으므로 **가장 큰 기술 리스크**다. 그래서 Phase 0에서 먼저 측정한다(R 13.4, 17.6).
- 이미 팀이 숙련된 엔진이 있다면 그것이 우선이다. **팀의 현재 숙련 엔진을 알려주면 순위를 다시 매긴다.**

확인이 필요한 사실: 엔진별 현재 라이선스·수수료 조건, 발헤임의 사용 엔진, Unity/Godot의 대형 지형 스트리밍 사례. Phase 0 첫 주에 공식 문서로 확인한다.

**Phase 0 엔진 게이트 통과 기준** (모두 **[가정]**, 수치는 확정 전 조정):
- 목표 최저 사양 기기에서 스트리밍 테스트 월드를 이동 중 프레임 드롭·히치 없이 통과.
- 전투·주목 카메라 프로토타입을 하루 내에 수정·재실행 가능한 이터레이션 속도.
- 지형 편집→배치→플레이 왕복이 10분 이내.
통과 못 하면 2순위 엔진으로 같은 4주 테스트를 한 번만 반복하고, 그래도 안 되면 월드를 "연결된 소규모 맵 여러 개"(R 18.3 Luban 3부: 더 롱 다크 방식)로 바꾼다.

## 3. 단계 개요

총 **약 30개월 + 버퍼 4개월** **[가정]**. 1~2인이면 각 단계를 1.5배로 늘리고 콘텐츠 목표를 줄인다.

| 단계 | 기간 | 목적 | 종료 게이트(통과 못 하면 다음 단계로 못 감) |
|---|---|---|---|
| P0 프리프로덕션 | 3개월 | 기둥·엔진·핵심 재미 검증 | 엔진 게이트 + 3개 프로토타입(전투 감, 규칙 상호작용, 이동) 재미 확인 |
| P1 수직 슬라이스 | 6개월 | 한 지역을 완성 품질로, 파이프라인 시간 측정 | 30~60분 플레이 가능, 제작 단가 실측, 최저사양 안정 |
| P2 콘텐츠 제작 (알파) | 10개월 | 전체 월드·던전·퀘스트 제작 | 엔딩까지 플레이 가능(거칠어도), 콘텐츠 컷 목록 확정 |
| P3 베타/폴리시 | 6개월 | 밸런스·UX·QA·접근성·최적화 | 치명 버그 0, 외부 플레이테스트 3회 |
| P4 출시/운영 | 5개월(3+버퍼 2) | 출시 준비·출시·초기 패치 | 출시, 출시 후 3개월 계획 확정 |
| 예비 | 4개월 | 일정 지연 흡수 | — |

단계 사이 **컷 회의**를 둔다. 조사 근거: 사이버펑크의 실패 요인에 범위 과다와 최저사양 확인 지연이 있고(R 14.4), 스코프는 슬라이스 실측치로 정해야 한다(R 14.3, 14.5).

## 5. 팀 구성안 **[제안]**

R B.8의 비율은 AAA 기준이며 C등급이라 소규모에 그대로 쓰지 못한다. 소규모에서는 역할을 겸임한다.

| 인원 | 구성 |
|---|---|
| 1명 (**선택됨**) | 전 역할 겸임. 외주·구매 없음(결정). 콘텐츠 목표를 1/3 이하로 줄여야 하며, 3년 이내 완성은 월드 크기를 크게 줄여야 함. 상세는 `dev-spec-phases.md` 부록 B |
| 3명 (기준안) | 프로그래머 2(게임플레이/월드·툴), 아티스트 1(모델링·애니·테크아트), 디자인·기획·프로듀스는 분담 |
| 5명 | 위 + 레벨/퀘스트 디자이너 1 + 아티스트 또는 사운드 1 |

외주: **없음(결정)**. 음악·사운드·애니메이션·번역·QA 모두 직접 제작. P1 종료 게이트에서 재검토 가능. 비용 수치는 R에 없음(R B.3 참조, 미확인).
